    Chapter 13. 알고리즘이란? - 효율적인 문제 해결의 시작¶

    🎯 이 장에서 배우는 것¶

    • 알고리즘의 정의와 좋은 알고리즘의 조건 3가지를 설명할 수 있다
    • 시간복잡도의 개념을 이해하고 빅오 표기법으로 표현할 수 있다
    • O(1), O(log n), O(n), O(n²)의 차이를 구분하고 비교할 수 있다
    • 간단한 코드를 보고 시간복잡도를 분석할 수 있다

    💡 왜 이걸 배우나요?¶

    여러분은 지금까지 파이썬의 기본 문법, 자료구조를 배웠습니다. 이제 "같은 문제를 어떻게 더 빠르게 풀 수 있을까?"를 고민할 차례입니다.

    간단한 질문 하나로 시작해볼까요?

    1부터 100까지의 합을 구하세요.

    방법 A는 1+2+3+...+100을 하나하나 더합니다. 방법 B는 공식 100×101÷2로 단번에 답을 냅니다. 두 방법 모두 정답은 5050이지만, 100이 아니라 10억이라면? 방법 A는 10억 번 더해야 하고, 방법 B는 여전히 한 번의 계산이면 됩니다.

    이것이 바로 알고리즘의 효율성이고, 프로그래머가 반드시 알아야 할 핵심 역량입니다. 이 장을 마치면, 코드를 보고 "이 코드는 데이터가 늘어나면 얼마나 느려질까?"를 판단할 수 있게 됩니다.

    📚 핵심 개념¶

    개념 1: 알고리즘이란?¶

    🍳 비유로 시작

    알고리즘은 요리 레시피와 같습니다. 된장찌개를 끓이려면:

    1. 냄비에 물을 붓는다
    2. 된장을 풀어 넣는다
    3. 두부와 채소를 넣는다
    4. 끓으면 불을 끈다

    이처럼 문제를 해결하기 위한 단계별 절차가 바로 알고리즘입니다. 레시피가 명확해야 누구나 같은 요리를 만들 수 있듯, 알고리즘도 명확해야 컴퓨터가 정확히 실행할 수 있습니다.

    📖 정확한 정의

    알고리즘(Algorithm): 주어진 문제를 해결하기 위해 정해진 규칙에 따라 수행하는 유한한 단계의 절차

    ✅ 좋은 알고리즘의 조건 3가지

    • 정확성: 올바른 결과를 내야 한다
    • 효율성: 시간과 메모리를 적게 사용해야 한다
    • 명확성: 각 단계가 모호하지 않고 분명해야 한다

    💬 생각해보기: 네비게이션 앱이 길을 안내할 때, "대충 오른쪽으로 가세요"라고 하면 어떨까요? "300m 후 우회전"처럼 명확해야 합니다. 알고리즘도 마찬가지입니다!

    개념 2: 같은 문제, 다른 효율 — 왜 "빠르기"가 중요한가?¶

    🏃 비유로 시작

    서울에서 부산까지 가는 방법은 여러 가지입니다. 걸어서 갈 수도 있고, KTX를 탈 수도 있죠. 둘 다 부산에 도착하지만, 걸리는 시간은 천지 차이입니다. 알고리즘도 마찬가지입니다.

    📖 예시로 확인 — 1부터 n까지의 합

    # 방법 A: 반복문으로 하나씩 더하기
def sum_loop(n):
    total = 0
    for i in range(1, n + 1):
        total += i
    return total

# 방법 B: 수학 공식 사용
def sum_formula(n):
    return n * (n + 1) // 2

    두 함수 모두 같은 결과를 돌려줍니다. 하지만 속도는 어떨까요?

    import time

n = 100_000_000  # 1억

start = time.time()
sum_loop(n)
end = time.time()
print(f"반복문: {end - start:.3f}초")

start = time.time()
sum_formula(n)
end = time.time()
print(f"공식:   {end - start:.6f}초")

    실행 결과 (대략적)

    • 반복문: 약 5~8초
    • 공식: 약 0.000001초

    n이 커질수록 차이는 더 벌어집니다. 이것이 알고리즘 효율성의 위력입니다!

    개념 3: 시간복잡도와 빅오 표기법¶

    📏 비유로 시작

    옷 사이즈를 말할 때 "S, M, L, XL"이라고 하지, 정확한 cm를 일일이 말하지 않습니다. 빅오 표기법도 마찬가지입니다. 알고리즘의 속도를 대략적인 등급으로 표현하는 방법입니다.

    📖 정확한 정의

    시간복잡도(Time Complexity): 입력 크기(n)가 커질 때, 연산 횟수가 어떻게 증가하는지를 나타내는 척도

    빅오 표기법(Big-O Notation): 시간복잡도를 최악의 경우 기준으로, 가장 빠르게 증가하는 항만 남겨 표현하는 방법

    핵심 규칙 2가지:

    • 상수는 무시한다: 3n → O(n)
    • 가장 큰 항만 남긴다: n² + 5n + 10 → O(n²)

    왜 이렇게 할까요? n이 매우 클 때, 작은 항은 영향력이 미미하기 때문입니다. n=1,000,000이면 n²은 1,000,000,000,000인데, 5n=5,000,000은 새 발의 피입니다.

    ✅ 예시로 확인 — 주요 4가지 복잡도

    graph LR A["⚡ O(1)<br/>상수 시간"] --> B["📈 O(log n)<br/>로그 시간"] B --> C["📊 O(n)<br/>선형 시간"] C --> D["🐢 O(n²)<br/>이차 시간"] style A fill:#22c55e,color:#fff style B fill:#3b82f6,color:#fff style C fill:#f59e0b,color:#fff style D fill:#ef4444,color:#fff

    각 복잡도를 하나씩 살펴봅시다.

    ⚡ O(1) — 상수 시간

    입력 크기에 상관없이 항상 같은 시간이 걸립니다.

    def get_first(data):
    return data[0]  # 리스트가 10개든 1억개든 한 번에 접근

    비유: 책의 목차를 보고 바로 원하는 페이지를 펼치는 것

    📈 O(log n) — 로그 시간

    데이터가 2배로 늘어도, 연산은 1번만 추가됩니다.

    def binary_hint(n):
    """n을 계속 반으로 나누면 몇 번 만에 1이 될까?"""
    count = 0
    while n > 1:
        n = n // 2
        count += 1
    return count

print(binary_hint(8))    # 3번 (8→4→2→1)
print(binary_hint(1024))  # 10번
print(binary_hint(1_000_000))  # 약 20번!

    비유: 업다운 게임. 1~100 중 숫자를 맞출 때, 매번 절반을 없애면 최대 7번이면 됩니다.

    📊 O(n) — 선형 시간

    데이터가 n개면 연산도 n번 필요합니다.

    def find_max(data):
    maximum = data[0]
    for item in data:  # n번 반복
        if item > maximum:
            maximum = item
    return maximum

    비유: 줄 서 있는 사람들에게 한 명씩 키를 물어보는 것

    🐢 O(n²) — 이차 시간

    반복문이 이중으로 중첩될 때 나타납니다.

    def has_duplicate(data):
    for i in range(len(data)):         # n번
        for j in range(i + 1, len(data)):  # 최대 n번
            if data[i] == data[j]:
                return True
    return False

    비유: 교실에서 모든 학생 쌍이 악수하는 것. 30명이면 435번의 악수!

    🔍 n이 커질수록 어떤 차이가 날까?

    n=10일 때와 n=10,000일 때를 비교해봅시다.

    • O(1): 1 → 1 (변화 없음)
    • O(log n): 약 3 → 약 13 (조금 증가)
    • O(n): 10 → 10,000 (1,000배)
    • O(n²): 100 → 100,000,000 (100만 배! 😱)

    개념 4: 코드를 보고 시간복잡도 판별하기¶

    실전에서 가장 중요한 능력입니다. 반복문의 구조를 보면 시간복잡도를 알 수 있습니다.

    판별 가이드:

    • 반복문 없음 → O(1)
    • 반복문 1개 (n번 반복) → O(n)
    • 반복문 2개 중첩 (n × n) → O(n²)
    • 반복할 때마다 절반으로 줄어듦 → O(log n)
    # 패턴 1: O(1) — 반복문 없음
def example_o1(n):
    return n * (n + 1) // 2

# 패턴 2: O(n) — 단일 반복문
def example_on(n):
    total = 0
    for i in range(n):
        total += i
    return total

# 패턴 3: O(n²) — 이중 반복문
def example_on2(n):
    count = 0
    for i in range(n):
        for j in range(n):
            count += 1
    return count

# 패턴 4: O(log n) — 매번 절반으로
def example_ologn(n):
    count = 0
    while n > 1:
        n = n // 2
        count += 1
    return count

    💬 알아보기: 반복문이 2개 있지만 중첩이 아니라 나란히 있으면? O(n) + O(n) = O(2n) = O(n) 입니다. 상수는 무시하니까요!

    🔨 따라하기¶

    직접 코드를 실행하며 시간복잡도의 차이를 눈으로 확인해봅시다.

    Step 1: 실행 시간 측정 함수 만들기¶

    import time

def measure_time(func, n):
    """함수의 실행 시간을 측정하는 도우미"""
    start = time.time()
    result = func(n)
    end = time.time()
    elapsed = end - start
    print(f"  n={n:>10,} → 결과: {result:>15,} | 시간: {elapsed:.6f}초")
    return elapsed

    Step 2: 네 가지 복잡도의 함수 정의하기¶

    def constant_time(n):
    """O(1): 항상 같은 연산"""
    return n * (n + 1) // 2

def log_time(n):
    """O(log n): 매번 절반으로"""
    count = 0
    temp = n
    while temp > 1:
        temp = temp // 2
        count += 1
    return count

def linear_time(n):
    """O(n): n번 반복"""
    total = 0
    for i in range(1, n + 1):
        total += i
    return total

def quadratic_time(n):
    """O(n²): 이중 반복"""
    count = 0
    for i in range(n):
        for j in range(n):
            count += 1
    return count

    Step 3: 다양한 n 값으로 실행하며 비교하기¶

    print("=" * 60)
print("⚡ O(1) - 상수 시간")
print("=" * 60)
for n in [100, 1_000, 10_000, 100_000]:
    measure_time(constant_time, n)

print()
print("=" * 60)
print("📈 O(log n) - 로그 시간")
print("=" * 60)
for n in [100, 1_000, 10_000, 100_000]:
    measure_time(log_time, n)

print()
print("=" * 60)
print("📊 O(n) - 선형 시간")
print("=" * 60)
for n in [100, 1_000, 10_000, 100_000]:
    measure_time(linear_time, n)

print()
print("=" * 60)
print("🐢 O(n²) - 이차 시간")
print("=" * 60)
for n in [100, 1_000, 10_000]:
    measure_time(quadratic_time, n)
print("  ⚠️ n=100,000은 너무 오래 걸려서 생략!")

    Step 4: 실행 결과 관찰하기¶

    직접 실행하면 이런 패턴을 발견할 수 있습니다:

    • O(1): n이 커져도 시간이 거의 0초
    • O(log n): n이 1,000배 커져도 시간 변화가 거의 없음
    • O(n): n이 10배 커지면 시간도 약 10배 증가
    • O(n²): n이 10배 커지면 시간이 약 100배 증가 😱

    Step 5: n이 10배 늘 때 시간 변화 확인하기¶

    print("\n📊 n이 10배 증가할 때 시간 변화 비교")
print("=" * 60)

# O(n)의 시간 변화
print("\nO(n) 비교:")
t1 = measure_time(linear_time, 100_000)

    Step 6: 비효율적 코드를 개선해보기¶

    # ❌ 비효율적: O(n²) - 리스트에서 중복 찾기
def find_duplicate_slow(data):
    for i in range(len(data)):
        for j in range(i + 1, len(data)):
            if data[i] == data[j]:
                return data[i]
    return None

# ✅ 효율적: O(n) - set을 활용한 중복 찾기
def find_duplicate_fast(data):
    seen = set()
    for item in data:
        if item in seen:       # set의 in 검사는 O(1)
            return item
        seen.add(item)
    return None

    📝 전체 코드¶

    아래 코드를 복사해서 한 번에 실행할 수 있습니다.

    import time
import random

# === 실행 시간 측정 도우미 ===
def measure_time(func, n):
    start = time.time()
    result = func(n)
    end = time.time()
    elapsed = end - start
    print(f"  n={n:>10,} | 시간: {elapsed:.6f}초")
    return elapsed

# === 네 가지 복잡도 함수 ===
def constant_time(n):      # O(1)
    return n * (n + 1) // 2

def log_time(n):            # O(log n)
    count = 0
    while n > 1:
        n //= 2
        count += 1
    return count

def linear_time(n):         # O(n)
    total = 0
    for i in range(1, n + 1):
        total += i
    return total

def quadratic_time(n):      # O(n²)
    count = 0
    for i in range(n):
        for j in range(n):
            count += 1
    return count

# === 실행 비교 ===
sizes = [1_000, 5_000, 10_000]

print("⚡ O(1) - 상수 시간")
for n in sizes:
    measure_time(constant_time, n)

print("\n📈 O(log n) - 로그 시간")
for n in sizes:
    measure_time(log_time, n)

print("\n📊 O(n) - 선형 시간")
for n in sizes:
    measure_time(linear_time, n)

print("\n🐢 O(n²) - 이차 시간")
for n in sizes:
    measure_time(quadratic_time, n)

    ⚠️ 자주 하는 실수¶

    실수 1: "반복문 개수 = 시간복잡도"라고 생각하기

    # 반복문이 2개지만 "나란히" 있으면 O(n) + O(n) = O(n)
for i in range(n):    # O(n)
    print(i)
for j in range(n):    # O(n)
    print(j)
# 전체: O(2n) → 상수 제거 → O(n) ✅

# 반복문이 2개 "중첩"이면 O(n²)
for i in range(n):        # O(n)
    for j in range(n):    # × O(n)
        print(i, j)
# 전체: O(n × n) = O(n²) ✅

    핵심: 나란히 = 더하기, 중첩 = 곱하기

    실수 2: 빅오에서 상수와 작은 항을 남기기

    실수 3: "빠른 알고리즘이 항상 좋다"고 생각하기

    O(n²) 알고리즘이라도 n이 매우 작으면 (예: n=10) 충분히 빠릅니다. 오히려 복잡한 O(n log n) 알고리즘보다 코드가 단순한 O(n²)이 유지보수에 유리할 수 있습니다. 중요한 것은 상황에 맞는 선택입니다.

    실수 4: O(log n)의 log 밑을 고민하기

    빅오 표기법에서 log₂n이든 log₁₀n이든 상수 배 차이이므로 구분하지 않습니다. 그냥 O(log n)이라고 씁니다.

    문제 5. n=1,000일 때, O(n)과 O(n²) 알고리즘의 연산 횟수는 대략 각각 얼마인가요?
