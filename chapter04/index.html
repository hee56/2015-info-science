    큐 - 줄 서기의 공정한 원칙¶

    🎯 이 장에서 배우는 것¶

    • 큐의 FIFO(선입선출) 원리를 이해하고 스택과의 차이를 명확히 구분할 수 있다
    • 리스트로 큐를 구현했을 때의 성능 문제를 설명할 수 있다
    • collections.deque를 활용하여 효율적인 큐를 구현하고 사용할 수 있다
    • 큐를 활용하여 대기열 시뮬레이션 등 실생활 문제를 모델링할 수 있다

    💡 왜 이걸 배우나요?¶

    여러분은 오늘도 줄을 섰습니다. 학교 급식 줄, 편의점 계산대, 버스 정류장. 먼저 온 사람이 먼저 서비스를 받는 이 당연한 원칙, 컴퓨터 세계에서도 똑같이 작동합니다.

    컴퓨터가 프린터에 문서 여러 개를 보내면? 먼저 보낸 문서가 먼저 출력됩니다. 유튜브 영상을 스트리밍할 때 데이터 패킷이 도착하는 순서대로 재생되는 것도 같은 원리입니다. 운영체제가 여러 프로그램의 요청을 처리하는 방식, 게임 서버가 플레이어의 접속을 순서대로 받아들이는 방식 — 모두 큐(Queue) 라는 자료구조 위에서 돌아갑니다.

    지난 장에서 배운 스택이 "마지막에 넣은 것을 먼저 꺼내는(LIFO)" 구조였다면, 큐는 정반대입니다. 먼저 넣은 것을 먼저 꺼내는(FIFO) 구조이죠. 이 한 가지 차이가 완전히 다른 활용 세계를 열어줍니다.

    📚 핵심 개념¶

    개념 1: 큐(Queue)란?¶

    🧃 비유로 시작 — 편의점 계산대

    편의점 계산대 앞에 세 사람이 줄을 서 있다고 상상해보세요.

    flowchart LR subgraph 계산대줄["🏪 편의점 계산대 줄"] direction LR A["🧑 민수\n(1번째 도착)"] --> B["👩 지영\n(2번째 도착)"] --> C["🧑‍🦱 현우\n(3번째 도착)"] end 계산대["💰 계산대\n(서비스)"] --> A D["🚶 새 손님\n(4번째 도착)"] --> C
    • 민수가 가장 먼저 왔으므로 가장 먼저 계산합니다
    • 새 손님은 줄의 맨 뒤에 섭니다
    • 새치기는 없습니다!

    📖 정확한 정의

    큐(Queue) 는 데이터를 한쪽 끝(rear, 뒤)에서 삽입하고, 반대쪽 끝(front, 앞)에서 삭제하는 선형 자료구조입니다. 이 원칙을 FIFO(First In, First Out, 선입선출) 라고 합니다.

    ✏️ 예시로 확인

    큐에 1, 2, 3을 순서대로 넣고 하나를 꺼내보겠습니다.

    flowchart LR subgraph 동작흐름["큐 동작 과정"] direction TB S1["① enqueue(1) → [1]"] S2["② enqueue(2) → [1, 2]"] S3["③ enqueue(3) → [1, 2, 3]"] S4["④ dequeue() → 1 반환, [2, 3]"] S1 --> S2 --> S3 --> S4 end

    가장 먼저 넣은 1이 가장 먼저 나옵니다. 이것이 FIFO입니다.

    개념 2: 큐의 핵심 연산¶

    큐에는 네 가지 핵심 연산이 있습니다.

    • enqueue(item) 🔵 — 큐의 뒤(rear) 에 데이터를 추가합니다. "줄의 맨 뒤에 선다"
    • dequeue() 🔴 — 큐의 앞(front) 에서 데이터를 꺼내고 반환합니다. "계산대에서 서비스를 받고 나간다"
    • peek() / front() 👀 — 큐의 맨 앞 데이터를 꺼내지 않고 확인만 합니다. "다음 차례가 누구인지 살짝 본다"
    • is_empty() ❓ — 큐가 비어있는지 확인합니다. "줄에 아무도 없나?"

    🔍 알아보기: 스택에서는 push/pop이었고, 큐에서는 enqueue/dequeue입니다. 이름만 달라진 게 아니라, 삽입과 삭제가 일어나는 위치가 다릅니다. 스택은 한쪽 끝에서만, 큐는 양쪽 끝에서 각각 일어납니다.

    개념 3: 스택 vs 큐 — 확실한 비교¶

    flowchart TB subgraph 스택["📚 스택 (LIFO)"] direction TB ST1["삽입(push) ↓"] --> TOP["맨 위\n(top)"] TOP --> ST2["삭제(pop) ↑"] end subgraph 큐["🚶‍♂️ 큐 (FIFO)"] direction LR QR["삽입(enqueue)\n→ rear"] --> MID[" 데이터 흐름 → "] --> QF["front →\n삭제(dequeue)"] end
    • 스택(LIFO) — 접시 쌓기. 마지막에 올린 접시를 먼저 꺼냄
    • 큐(FIFO) — 줄 서기. 먼저 선 사람이 먼저 나감

    💭 생각해보기: 카카오톡 메시지는 보낸 순서대로 상대방에게 도착합니다. 이것은 스택일까요, 큐일까요? → 큐입니다! 먼저 보낸 메시지가 먼저 도착하는 FIFO 방식이죠.

    개념 4: 리스트의 한계와 deque의 등장¶

    파이썬 리스트로 큐를 만들 수 있을까요? 가능하지만, 심각한 성능 문제가 있습니다.

    # 리스트로 만든 큐 (비효율적!)
queue = []
queue.append(1)   # enqueue: 뒤에 추가 → O(1) ✅ 빠름
queue.append(2)
queue.append(3)

queue.pop(0)       # dequeue: 앞에서 제거 → O(n) ❌ 느림!

    pop(0)을 하면 맨 앞 원소를 제거한 뒤, 나머지 모든 원소를 한 칸씩 앞으로 이동시켜야 합니다. 데이터가 100만 개라면? 한 번 꺼낼 때마다 100만 번 이동합니다.

    flowchart TB subgraph 문제["pop(0)의 문제점"] direction TB B1["[1, 2, 3, 4, 5] 에서 pop(0)"] B2["1을 제거"] B3["2→칸1, 3→칸2, 4→칸3, 5→칸4 이동"] B4["[2, 3, 4, 5] 완성"] B1 --> B2 --> B3 --> B4 end

    💊 해결책: collections.deque

    deque(덱, Double-Ended Queue)는 양쪽 끝에서 삽입/삭제가 모두 O(1) 인 자료구조입니다.

    from collections import deque

queue = deque()
queue.append(1)      # enqueue: 뒤에 추가 → O(1) ✅
queue.append(2)
queue.append(3)

queue.popleft()      # dequeue: 앞에서 제거 → O(1) ✅

    📌 정리하기: 파이썬에서 큐를 구현할 때는 리스트 대신 반드시 collections.deque를 사용하세요. append()로 넣고, popleft()로 꺼내면 됩니다.

    🔨 따라하기: 은행 창구 대기열 시뮬레이션¶

    은행에 손님이 도착하고, 창구에서 차례대로 서비스를 받는 상황을 시뮬레이션해봅시다. 평균 대기 시간이 얼마인지 계산합니다.

    Step 1: 기본 큐 클래스 만들기¶

    deque를 감싸서 우리만의 큐 클래스를 만들어봅시다.

    from collections import deque

class Queue:
    def __init__(self):
        self._data = deque()

    def enqueue(self, item):
        """큐의 뒤에 데이터 추가"""
        self._data.append(item)

    def dequeue(self):
        """큐의 앞에서 데이터 꺼내기"""
        if self.is_empty():
            raise IndexError("큐가 비어있습니다!")
        return self._data.popleft()

    def peek(self):
        """맨 앞 데이터 확인 (제거하지 않음)"""
        if self.is_empty():
            raise IndexError("큐가 비어있습니다!")
        return self._data[0]

    def is_empty(self):
        """큐가 비어있는지 확인"""
        return len(self._data) == 0

    def size(self):
        """큐의 크기 반환"""
        return len(self._data)

    def __str__(self):
        return f"Queue(front → {list(self._data)} ← rear)"

    Step 2: 큐 클래스 테스트하기¶

    q = Queue()
q.enqueue("민수")
q.enqueue("지영")
q.enqueue("현우")
print(q)           # Queue(front → ['민수', '지영', '현우'] ← rear)

print(q.dequeue()) # 민수 (가장 먼저 들어온 사람)
print(q.peek())    # 지영 (다음 차례)
print(q.size())    # 2
print(q)           # Queue(front → ['지영', '현우'] ← rear)

    Step 3: 손님 데이터 준비하기¶

    각 손님의 도착 시간과 서비스에 걸리는 시간을 정의합니다.

    # (손님 이름, 도착 시간(분), 서비스 소요 시간(분))
customers = [
    ("민수", 0, 3),
    ("지영", 1, 4),
    ("현우", 3, 2),
    ("수아", 5, 5),
    ("도윤", 6, 3),
]

    Step 4: 시뮬레이션 로직 작성¶

    def simulate_bank(customers):
    wait_queue = Queue()
    current_time = 0       # 현재 시각
    service_end_time = 0   # 현재 서비스가 끝나는 시각
    total_wait = 0         # 총 대기 시간
    served_count = 0       # 서비스 완료한 손님 수

    customer_index = 0     # 다음 도착할 손님의 인덱스

    print("⏰ 시뮬레이션 시작!\n")

    while customer_index < len(customers) or not wait_queue.is_empty():
        # 현재 시각에 도착하는 손님을 큐에 추가
        while (customer_index < len(customers)
               and customers[customer_index][1] <= current_time):
            name, arrival, service = customers[customer_index]
            wait_queue.enqueue((name, arrival, service))
            print(f"  [{current_time}분] 🚶 {name} 도착 → 대기열에 합류 (대기: {wait_queue.size()}명)")
            customer_index += 1

        # 창구가 비었고 대기열에 손님이 있으면 서비스 시작
        if current_time >= service_end_time and not wait_queue.is_empty():
            name, arrival, service = wait_queue.dequeue()
            wait_time = current_time - arrival
            total_wait += wait_time
            served_count += 1
            service_end_time = current_time + service
            print(f"  [{current_time}분] 💰 {name} 서비스 시작 (대기 {wait_time}분, 소요 {service}분)")

        current_time += 1

    avg_wait = total_wait / served_count if served_count > 0 else 0
    print(f"\n📊 결과: {served_count}명 서비스 완료, 평균 대기 시간 = {avg_wait:.1f}분")
    return avg_wait

    Step 5: 시뮬레이션 실행¶

    simulate_bank(customers)

    💭 생각해보기: 창구가 2개라면 평균 대기 시간이 어떻게 변할까요? Step 4의 코드를 수정해서 창구를 늘려보세요. 이런 시뮬레이션은 실제로 은행, 병원, 콜센터 등에서 적정 직원 수를 결정하는 데 사용됩니다!

    📝 전체 코드¶

    from collections import deque


# === 큐 클래스 ===
class Queue:
    def __init__(self):
        self._data = deque()

    def enqueue(self, item):
        self._data.append(item)

    def dequeue(self):
        if self.is_empty():
            raise IndexError("큐가 비어있습니다!")
        return self._data.popleft()

    def peek(self):
        if self.is_empty():
            raise IndexError("큐가 비어있습니다!")
        return self._data[0]

    def is_empty(self):
        return len(self._data) == 0

    def size(self):
        return len(self._data)

    def __str__(self):
        return f"Queue(front → {list(self._data)} ← rear)"


# === 은행 창구 시뮬레이션 ===
def simulate_bank(customers):
    wait_queue = Queue()
    current_time = 0
    service_end_time = 0
    total_wait = 0
    served_count = 0
    customer_index = 0

    print("⏰ 시뮬레이션 시작!\n")

    while customer_index < len(customers) or not wait_queue.is_empty():
        while (customer_index < len(customers)
               and customers[customer_index][1] <= current_time):
            name, arrival, service = customers[customer_index]
            wait_queue.enqueue((name, arrival, service))
            print(f"  [{current_time}분] 🚶 {name} 도착 (대기: {wait_queue.size()}명)")
            customer_index += 1

        if current_time >= service_end_time and not wait_queue.is_empty():
            name, arrival, service = wait_queue.dequeue()
            wait_time = current_time - arrival
            total_wait += wait_time
            served_count += 1
            service_end_time = current_time + service
            print(f"  [{current_time}분] 💰 {name} 서비스 시작 (대기 {wait_time}분)")

        current_time += 1

    avg_wait = total_wait / served_count if served_count > 0 else 0
    print(f"\n📊 결과: {served_count}명 완료, 평균 대기 시간 = {avg_wait:.1f}분")
    return avg_wait


# === 실행 ===
customers = [
    ("민수", 0, 3),
    ("지영", 1, 4),
    ("현우", 3, 2),
    ("수아", 5, 5),
    ("도윤", 6, 3),
]

simulate_bank(customers)

    실수 3: enqueue와 dequeue 방향을 혼동한다 🔄

    from collections import deque
q = deque()

# ❌ 방향 혼동 — append와 pop을 같은 쪽에서 사용하면 스택!
q.append(1)

    응용 문제: 다음 코드의 출력 결과를 예측하세요.

    from collections import deque

def hot_potato(names, count):
    """뜨거운 감자 게임: count번째 사람이 탈락"""
    q = deque(names)
    while len(q) > 1:
        for _ in range(count):
            q.append(q.popleft())  # 앞에서 빼서 뒤로 보냄
        eliminated = q.popleft()
        print(f"{eliminated} 탈락!")
    return q[0]

winner = hot_potato(["A", "B", "C", "D", "E"], 3)
print(f"🏆 승자: {winner}")
    정답 확인 
    C 탈락!
A 탈락!
E 탈락!
B 탈락!
🏆 승자: D
    이 게임은 **요세푸스 문제**라고 불리며, 큐의 회전(rotation)을 활용한 대표적인 예제입니다. `popleft()`로 꺼내서 `append()`로 뒤에 붙이면 큐가 원형으로 회전하는 효과를 냅니다.

    🚀 더 해보기¶

    도전: 원형 큐 구현하기

    원형 큐(Circular Queue)는 배열의 끝에 도달하면 다시 처음으로 돌아가는 구조입니다. 고정된 크기의 배열로 큐를 효율적으로 구현할 수 있습니다.

    flowchart LR subgraph 원형큐["🔄 원형 큐 (크기 5)"] direction LR P0["[0]"] --> P1["[1]"] --> P2["[2]"] --> P3["[3]"] --> P4["[4]"] --> P0 end
    class CircularQueue:
    def __init__(self, capacity):
        self._data = [None] * capacity
        self._capacity = capacity
        self._front = 0
        self._rear = 0
        self._size = 0

    def enqueue(self, item):
        if self._size == self._capacity:
            raise OverflowError("큐가 가득 찼습니다!")
        self._data[self._rear] = item
        self._rear = (self._rear + 1) % self._capacity  # 핵심! 나머지 연산으로 순환
        self._size += 1

    def dequeue(self):
        if self._size == 0:
            raise IndexError("큐가 비어있습니다!")
        item = self._data[self._front]
        self._data[self._front] = None
        self._front = (self._front + 1) % self._capacity  # 핵심!
        self._size -= 1
        return item

    def __str__(self):
        return f"CircularQueue({self._data}, front={self._front}, rear={self._rear})"


# 테스트
cq = CircularQueue(4)
cq.enqueue("A")
cq.enqueue("B")
cq.enqueue("C")
print(cq)              # CircularQueue(['A', 'B', 'C', None], front=0, rear=3)
print(cq.dequeue())    # A
print(cq.dequeue())    # B
cq.enqueue("D")
cq.enqueue("E")
print(cq)              # CircularQueue([None, None, 'C', 'D'], ... → 'E'가 인덱스 0으로!

    🔍 알아보기: % self._capacity(나머지 연산)가 원형 큐의 핵심입니다. 인덱스가 배열 끝에 도달하면 자동으로 0으로 돌아갑니다. 이 기법은 운영체제의 버퍼 관리, 네트워크의 패킷 버퍼 등에서 실제로 사용됩니다.

    📌 핵심 개념 요약¶

    • 큐(Queue) — FIFO(선입선출) 원칙을 따르는 자료구조
    • 핵심 연산 — enqueue(뒤에 삽입), dequeue(앞에서 삭제), peek(앞 확인), is_empty(비어있는지 확인)
    • 파이썬 구현 — collections.deque의 append()와 popleft() 조합 사용 (리스트의 pop(0)은 O(n)이므로 사용 금지!)
    • 원형 큐 — 나머지 연산(%)으로 배열을 순환하여 고정 크기 큐를 효율적으로 구현
