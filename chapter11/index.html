    Chapter 11. 그래프 탐색 — DFS와 BFS로 길 찾기¶

    Part 3 | [1권] 그래프와 자료구조 종합

    🎯 이 장에서 배우는 것¶

    • 깊이 우선 탐색(DFS)의 탐색 순서를 그림으로 추적할 수 있다
    • 너비 우선 탐색(BFS)의 탐색 순서를 그림으로 추적할 수 있다
    • 스택(재귀)을 이용한 DFS, 큐를 이용한 BFS를 파이썬으로 구현할 수 있다
    • 문제 상황에 따라 DFS와 BFS 중 적절한 탐색 방법을 선택할 수 있다

    💡 왜 이걸 배우나요?¶

    여러분이 거대한 미로에 갇혀 있다고 상상해 보세요. 출구를 찾으려면 길을 탐색하는 전략이 필요합니다.

    • 전략 A — 갈림길이 나오면 하나를 골라 끝까지 가본다. 막히면 되돌아와서 다른 길을 시도한다.
    • 전략 B — 현재 위치에서 한 걸음씩 모든 방향으로 동시에 퍼져 나간다. 마치 물이 퍼지듯!

    전략 A가 DFS(깊이 우선 탐색), 전략 B가 BFS(너비 우선 탐색) 입니다.

    네비게이션의 최단 경로, 소셜 네트워크의 "나와 몇 다리 건너 아는 사이인지", 게임 AI의 경로 탐색 — 이 모든 것이 DFS와 BFS 위에서 동작합니다. 그래프를 만드는 법은 이미 배웠으니, 이제 그래프 위를 걸어 다니는 법을 익혀 봅시다! 🚶‍♂️

    📚 핵심 개념¶

    개념 1: DFS — 깊이 우선 탐색 🕳️¶

    비유로 시작

    동굴 탐험가를 떠올려 보세요. 갈림길에서 왼쪽 통로를 골라 끝까지 들어갑니다. 막다른 곳에 다다르면 가장 최근 갈림길로 되돌아와 아직 가보지 않은 통로를 다시 끝까지 탐험합니다.

    정확한 정의

    DFS(Depth-First Search) 는 그래프에서 한 정점을 시작으로, 방문하지 않은 인접 정점을 하나 골라 가능한 깊이 들어간 뒤, 더 이상 갈 곳이 없으면 되돌아오며(백트래킹) 탐색을 이어가는 방법입니다.

    핵심 도구 — 스택 또는 재귀 호출 (재귀 자체가 내부적으로 호출 스택을 사용합니다)

    예시로 확인

    아래 그래프를 DFS로 탐색해 봅시다 (시작: 정점 0).

    graph LR 0 --- 1 0 --- 2 1 --- 3 1 --- 4 2 --- 5

    탐색 과정 (인접 리스트가 작은 번호 순으로 정렬되어 있다고 가정):

    1. 0 방문 → 인접: 1, 2 → 1을 선택해 깊이 진입
    2. 1 방문 → 인접: 0(방문됨), 3, 4 → 3을 선택
    3. 3 방문 → 인접: 1(방문됨) → 막다른 길! 되돌아감
    4. 1로 복귀 → 4를 선택
    5. 4 방문 → 인접: 1(방문됨) → 되돌아감
    6. 0으로 복귀 → 2를 선택
    7. 2 방문 → 인접: 0(방문됨), 5 → 5를 선택
    8. 5 방문 → 탐색 완료!

    📌 방문 순서: 0 → 1 → 3 → 4 → 2 → 5

    개념 2: BFS — 너비 우선 탐색 🌊¶

    비유로 시작

    잔잔한 호수에 돌을 던지면 동심원이 퍼져 나갑니다. BFS도 마찬가지예요. 시작점에서 1걸음 거리 정점을 모두 방문하고, 그 다음 2걸음 거리 정점을 모두 방문하는 식으로 점점 넓게 퍼집니다.

    정확한 정의

    BFS(Breadth-First Search) 는 시작 정점에서 가까운 정점부터 층(level) 단위로 탐색하는 방법입니다. 같은 거리의 정점을 모두 처리한 뒤 다음 거리로 나아갑니다.

    핵심 도구 — 큐(Queue)

    예시로 확인

    같은 그래프를 BFS로 탐색합니다 (시작: 정점 0).

    graph LR 0 --- 1 0 --- 2 1 --- 3 1 --- 4 2 --- 5
    1. 0 방문, 큐에 인접 정점 넣기 → 큐: [1, 2]
    2. 큐에서 1 꺼내 방문, 인접 정점 넣기 → 큐: [2, 3, 4]
    3. 큐에서 2 꺼내 방문, 인접 정점 넣기 → 큐: [3, 4, 5]
    4. 큐에서 3 꺼내 방문 → 큐: [4, 5]
    5. 큐에서 4 꺼내 방문 → 큐: [5]
    6. 큐에서 5 꺼내 방문 → 큐: [] → 탐색 완료!

    📌 방문 순서: 0 → 1 → 2 → 3 → 4 → 5

    DFS는 깊이 방향으로 파고들어 3, 4를 먼저 방문했고, BFS는 0에서 가까운 1, 2를 먼저 방문한 뒤 다음 층으로 이동했습니다.

    개념 3: DFS vs BFS — 한눈에 비교¶

    flowchart LR subgraph DFS direction TB D1["자료구조: 스택 / 재귀"] D2["탐색 방향: 깊이 ↓"] D3["유리한 상황: 경로 존재 여부, 모든 경우 탐색"] end subgraph BFS direction TB B1["자료구조: 큐"] B2["탐색 방향: 너비 →"] B3["유리한 상황: 최단 거리·최소 횟수"] end

    🔑 알아보기: "최단 거리를 구하라"는 문제 → BFS, "가능한 모든 경로를 탐색하라"는 문제 → DFS 를 먼저 떠올리세요!

    개념 4: visited — 방문 기록이 꼭 필요한 이유¶

    그래프에는 순환(cycle) 이 있을 수 있습니다. 방문 기록 없이 탐색하면 같은 정점을 무한히 반복 방문하게 됩니다!

    visited 집합(set) 또는 리스트를 사용해 이미 방문한 정점을 기록하고, 방문한 정점은 다시 방문하지 않습니다.

    🔨 따라하기¶

    아래 그래프를 파이썬 코드로 만들고, DFS와 BFS를 직접 구현해 봅시다.

    graph LR 0 --- 1 0 --- 2 1 --- 3 1 --- 4 2 --- 5 3 --- 5

    Step 1: 그래프를 인접 리스트로 표현하기¶

    # 딕셔너리로 인접 리스트 구성
graph = {
    0: [1, 2],
    1: [0, 3, 4],
    2: [0, 5],
    3: [1, 5],
    4: [1],
    5: [2, 3]
}

    💡 생각해보기: 정점 3과 5 사이에 간선이 추가되었습니다. 순환이 생겼을까요? 0→1→3→5→2→0 — 네, 순환이 존재합니다! visited가 더욱 중요하겠죠?

    Step 2: 재귀로 DFS 구현하기¶

    def dfs(graph, node, visited=None):
    if visited is None:
        visited = set()

    visited.add(node)          # 현재 정점 방문 처리
    print(node, end=' ')       # 방문 순서 출력

    for neighbor in graph[node]:
        if neighbor not in visited:
            dfs(graph, neighbor, visited)  # 재귀 호출 = 스택 push

    return visited

    실행:

    print("DFS 방문 순서:")
dfs(graph, 0)

    출력: 0 1 3 5 2 4

    📌 정리하기: 재귀 호출이 곧 스택의 push, 함수 종료(리턴)가 곧 스택의 pop입니다. Chapter 7에서 배운 스택이 여기서 활용됩니다!

    Step 3: 큐로 BFS 구현하기¶

    from collections import deque

def bfs(graph, start):
    visited = set([start])     # 시작 정점 방문 처리
    queue = deque([start])     # 큐에 시작 정점 넣기
    order = []                 # 방문 순서 기록

    while queue:
        node = queue.popleft()     # 큐에서 꺼내기 (FIFO)
        order.append(node)

        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)  # ★ 큐에 넣을 때 방문 처리!
                queue.append(neighbor)

    return order

    실행:

    print("BFS 방문 순서:")
print(bfs(graph, 0))

    출력: [0, 1, 2, 3, 4, 5]

    Step 4: 같은 그래프, 두 결과 비교하기¶

    print("=== 탐색 비교 ===")
print("DFS:", end=' ')
dfs(graph, 0)
print()
print("BFS:", bfs(graph, 0))

    === 탐색 비교 ===
DFS: 0 1 3 5 2 4
BFS: [0, 1, 2, 3, 4, 5]

    DFS는 0→1→3→5 방향으로 깊이 파고들었고, BFS는 0에서 1, 2를 먼저 모두 방문한 뒤 다음 층으로 넘어갔습니다.

    Step 5: 두 정점이 연결되어 있는지 확인하기 (응용)¶

    def is_connected(graph, start, goal):
    """BFS로 start에서 goal까지 갈 수 있는지 확인"""
    visited = set([start])
    queue = deque([start])

    while queue:
        node = queue.popleft()
        if node == goal:
            return True
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)

    return False

# 테스트
print(is_connected(graph, 0, 5))  # True
print(is_connected(graph, 4, 5))  # True

    Step 6: 스택을 직접 사용한 DFS (비재귀 버전)¶

    재귀 대신 스택 자료구조를 직접 사용하면 DFS의 원리가 더 명확하게 보입니다.

    def dfs_stack(graph, start):
    visited = set()
    stack = [start]            # 리스트를 스택으로 사용
    order = []

    while stack:
        node = stack.pop()        # 스택에서 꺼내기 (LIFO)
        if node not in visited:
            visited.add(node)
            order.append(node)
            # 인접 정점을 역순으로 넣어야 작은 번호부터 방문
            for neighbor in reversed(graph[node]):
                if neighbor not in visited:
                    stack.append(neighbor)

    return order

print("DFS(스택):", dfs_stack(graph, 0))

    출력: DFS(스택): [0, 1, 3, 5, 2, 4]

    🔑 알아보기: BFS 코드에서 deque와 popleft()를 list와 pop()으로 바꾸면 — 큐가 스택으로 변하면서 BFS가 DFS로 바뀝니다! 자료구조 하나 차이로 탐색 방식이 완전히 달라지는 것이죠.

    📝 전체 코드¶

    from collections import deque

# 그래프 정의 (인접 리스트)
graph = {
    0: [1, 2],
    1: [0, 3, 4],
    2: [0, 5],
    3: [1, 5],
    4: [1],
    5: [2, 3]
}

# ---- DFS (재귀) ----
def dfs(graph, node, visited=None):
    if visited is None:
        visited = set()
    visited.add(node)
    print(node, end=' ')
    for neighbor in graph[node]:
        if neighbor not in visited:
            dfs(graph, neighbor, visited)
    return visited

# ---- DFS (스택) ----
def dfs_stack(graph, start):
    visited = set()
    stack = [start]
    order = []
    while stack:
        node = stack.pop()
        if node not in visited:
            visited.add(node)
            order.append(node)
            for neighbor in reversed(graph[node]):
                if neighbor not in visited:
                    stack.append(neighbor)
    return order

# ---- BFS (큐) ----
def bfs(graph, start):
    visited = set([start])
    queue = deque([start])
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    return order

# ---- 연결 여부 확인 ----
def is_connected(graph, start, goal):
    visited = set([start])
    queue = deque([start])
    while queue:
        node = queue.popleft()
        if node == goal:
            return True
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
    return False

# 실행
print("DFS(재귀):", end=' ')
dfs(graph, 0)
print()
print("DFS(스택):", dfs_stack(graph, 0))
print("BFS:      ", bfs(graph, 0))
print("0→5 연결?", is_connected(graph, 0, 5))

    ⚠️ 자주 하는 실수¶

    실수 1: visited 처리를 빼먹는다 😵

    # ❌ 잘못된 코드 — 무한 루프 발생!
def bad_bfs(graph, start):
    queue = deque([start])
    while queue:
        node = queue.popleft()
        print(node)
        for neighbor in graph[node]:
            queue.append(neighbor)  # 방문 확인 없이 무조건 추가

    순환이 있는 그래프에서 이 코드는 영원히 끝나지 않습니다. 반드시 visited를 사용하세요.

    실수 2: BFS에서 "큐에 넣을 때" 가 아니라 "꺼낼 때" 방문 처리한다 🔄

    # ❌ 비효율적 — 같은 정점이 큐에 여러 번 들어감
while queue:
    node = queue.popleft()
    if node in visited:    # 꺼낸 후에 체크
        continue
    visited.add(node)
    for neighbor in graph[node]:
        queue.append(neighbor)  # 방문 체크 없이 추가

    BFS에서는 큐에 넣는 시점에 visited 처리해야 중복 삽입을 방지할 수 있습니다.

    실수 3: 재귀 DFS에서 visited를 기본값 set()으로 쓴다 ⚙️

    # ❌ 위험! — 파이썬 기본값은 함수 호출 간 공유됨
def dfs(graph, node, visited=set()):  # 절대 이렇게 쓰지 마세요!
    ...

    파이썬의 가변 기본값(mutable default argument) 문제입니다. 두 번째 호출 시 이전 visited가 남아 있어 엉뚱한 결과가 나옵니다. None을 기본값으로 쓰고 함수 안에서 새로 만드세요.

    ✅ 스스로 점검하기¶

    기본 문제 — 탐색 순서 추적 ✏️

    아래 그래프에서 정점 A부터 DFS와 BFS의 방문 순서를 종이에 적어 보세요 (알파벳 순서로 선택).

    graph LR A --- B A --- C B --- D B --- E C --- F

    정답 - DFS: A → B → D → E → C → F - BFS: A → B → C → D → E → F

    응용 문제 — 코드 수정 🛠️

    bfs 함수를 수정하여 방문 순서뿐 아니라 각 정점까지의 거리(시작 정점으로부터 몇 걸음)도 함께 반환하도록 만들어 보세요.

    힌트: 딕셔너리 distance를 만들고, 시작 정점은 0, 인접 정점은 현재 정점의 거리 + 1로 설정합니다.

    정답 보기 
    def bfs_with_distance(graph, start):
    visited = set([start])
    queue = deque([start])
    distance = {start: 0}

    while queue:
        node = queue.popleft()
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append(neighbor)
                distance[neighbor] = distance[node] + 1

    return distance

print(bfs_with_distance(graph, 0))
# {0: 0, 1: 1, 2: 1, 3: 2, 4: 2, 5: 2}
