    15장. 고급 정렬 - 퀵 정렬과 병합 정렬¶

    Part 4 | [2권] 알고리즘의 기초 - 정렬과 탐색

    🎯 이 장에서 배우는 것¶

    • 분할 정복(Divide and Conquer) 전략의 핵심 아이디어를 설명할 수 있다
    • 퀵 정렬의 피벗 선택과 파티션 과정을 단계별로 추적할 수 있다
    • 병합 정렬의 분할·병합 과정을 추적하고 파이썬으로 구현할 수 있다
    • O(n log n) 정렬이 O(n²) 정렬보다 왜 빠른지 이해하고 실험으로 확인할 수 있다

    💡 왜 이걸 배우나요?¶

    14차시에서 배운 선택 정렬, 삽입 정렬은 이해하기 쉽지만, 데이터가 많아지면 극적으로 느려집니다. 1,000개를 정렬하는 데 1초 걸렸다면, 10,000개는 1초가 아니라 100초가 걸릴 수 있습니다(O(n²)의 특성).

    📦 비유: 책꽂이 정리

    방 가득 쌓인 책 200권을 정리한다고 상상해 보세요. - 방법 A (기본 정렬): 전체를 훑으며 가장 작은 번호를 찾고, 또 훑고, 또 훑고… 😩 - 방법 B (분할 정복): 먼저 "100번 이하 / 101번 이상"으로 두 더미로 나눈 뒤, 각 더미 안에서만 정리한다. 더미가 작으니 금방 끝! 🎉

    이번 장에서 배우는 퀵 정렬과 병합 정렬은 바로 이 "나눠서 정복하기" 전략을 사용합니다. 실무에서 사용되는 거의 모든 정렬 라이브러리(파이썬의 sorted() 포함)가 이 아이디어를 기반으로 만들어져 있습니다.

    📚 핵심 개념¶

    개념 1: 분할 정복(Divide and Conquer)¶

    1) 비유로 시작

    시험 채점지 100장을 혼자 정렬해야 합니다. 전부 한꺼번에 하면 막막하지만, 이렇게 하면 어떨까요?

    1. 분할(Divide): 대충 절반으로 나눈다 → 50장씩 두 묶음
    2. 정복(Conquer): 각 묶음을 정렬한다 (묶음이 크면 또 나눈다)
    3. 결합(Combine): 정렬된 두 묶음을 합쳐 하나의 정렬된 결과를 만든다

    2) 정확한 정의

    🔑 분할 정복이란, 큰 문제를 같은 형태의 작은 문제로 나누고, 작은 문제의 답을 합쳐 원래 문제의 답을 구하는 알고리즘 설계 전략입니다. 재귀(자기 자신을 호출)와 함께 사용됩니다.

    3) 예시로 확인

    graph TD A["[5, 3, 8, 1, 2, 7, 4, 6]<br>👈 원래 문제"] --> B["[5, 3, 8, 1]<br>분할"] A --> C["[2, 7, 4, 6]<br>분할"] B --> D["[1, 3, 5, 8]<br>정복: 정렬됨"] C --> E["[2, 4, 6, 7]<br>정복: 정렬됨"] D --> F["[1, 2, 3, 4, 5, 6, 7, 8]<br>✅ 결합"] E --> F

    개념 2: 퀵 정렬(Quick Sort)¶

    1) 비유로 시작

    교실에서 키 순서대로 줄을 세운다고 합시다. 선생님이 한 명을 기준(피벗)으로 세우고 "이 친구보다 작은 사람은 왼쪽, 큰 사람은 오른쪽!"이라고 외칩니다. 그런 다음 왼쪽 그룹, 오른쪽 그룹에서 같은 작업을 반복하면 결국 모두 줄이 서게 됩니다.

    2) 정확한 정의

    🔑 퀵 정렬은 리스트에서 피벗(pivot) 하나를 고르고, 피벗보다 작은 값은 왼쪽, 큰 값은 오른쪽으로 파티션(분류) 한 뒤, 양쪽을 재귀적으로 정렬하는 알고리즘입니다.

    3) 단계별 추적 예시

    리스트 [5, 3, 8, 1, 2, 7, 4, 6]에서 마지막 원소를 피벗으로 선택합니다.

    graph TD A["[5, 3, 8, 1, 2, 7, 4, 6]<br>피벗 = 6"] --> B["왼쪽: [5, 3, 1, 2, 4]<br>(6보다 작거나 같은 것)"] A --> P1["[6]<br>피벗 자리 확정 ✅"] A --> C["오른쪽: [8, 7]<br>(6보다 큰 것)"] B --> D["[3, 1, 2]"] B --> P2["[4] 확정"] B --> E["[5]"] C --> F["[7]"] C --> P3["[8] 확정"]

    파티션을 반복하면 모든 원소가 제자리를 찾습니다.

    개념 3: 병합 정렬(Merge Sort)¶

    1) 비유로 시작

    카드 두 묶음이 각각 이미 오름차순으로 정렬되어 있다면, 두 묶음을 하나로 합치는 건 쉽습니다. 양쪽 맨 앞 카드만 비교해서 작은 걸 꺼내면 되니까요! 병합 정렬은 이 아이디어를 이용합니다.

    2) 정확한 정의

    🔑 병합 정렬은 리스트를 절반씩 계속 나누어 원소가 1개가 될 때까지 쪼갠 뒤, 정렬하면서 합치는(merge) 알고리즘입니다.

    3) 단계별 추적 예시

    graph TD A["[5, 3, 8, 1]"] --> B["[5, 3]"] A --> C["[8, 1]"] B --> D["[5]"] B --> E["[3]"] C --> F["[8]"] C --> G["[1]"] D --> H["[3, 5] ← 병합"] E --> H F --> I["[1, 8] ← 병합"] G --> I H --> J["[1, 3, 5, 8] ← 최종 병합 ✅"] I --> J

    병합할 때 양쪽의 맨 앞끼리 비교하여 작은 것부터 새 리스트에 넣습니다.

    개념 4: 시간 복잡도 비교 — O(n²) vs O(n log n)¶

    왜 더 빠를까요?

    • 기본 정렬 (선택/삽입): 데이터 n개에 대해 매번 전체를 훑음 → 비교 횟수 약 n × n = n²
    • 고급 정렬 (퀵/병합): 절반씩 나누는 깊이가 log n단계이고, 각 단계마다 총 n번 비교 → 총 약 n × log n

    💡 알아보기: 숫자로 느끼기

    • n = 1,000일 때: n² = 1,000,000 vs n log n ≈ 10,000 → 약 100배 차이!
    • n = 100,000일 때: n² = 10,000,000,000 vs n log n ≈ 1,700,000 → 약 6,000배 차이!
    graph LR subgraph "데이터가 늘어날수록 격차 폭발 💥" A["n = 100<br>O n² = 10,000<br>O n log n ≈ 664"] B["n = 10,000<br>O n² = 100,000,000<br>O n log n ≈ 133,000"] end

    🔑 정리하기: 퀵 정렬 평균 O(n log n), 최악 O(n²). 병합 정렬 항상 O(n log n). 추가 메모리는 병합 정렬이 더 필요합니다.

    🔨 따라하기¶

    Step 1: 퀵 정렬 구현하기¶

    def quick_sort(arr):
    if len(arr) <= 1:
        return arr

    pivot = arr[-1]  # 마지막 원소를 피벗으로
    left = [x for x in arr[:-1] if x <= pivot]   # 피벗 이하
    right = [x for x in arr[:-1] if x > pivot]    # 피벗 초과

    return quick_sort(left) + [pivot] + quick_sort(right)

# 테스트
data = [5, 3, 8, 1, 2, 7, 4, 6]
print("정렬 전:", data)
print("정렬 후:", quick_sort(data))

    실행 결과: 

    정렬 전: [5, 3, 8, 1, 2, 7, 4, 6]
정렬 후: [1, 2, 3, 4, 5, 6, 7, 8]

    💡 생각해보기: left와 right를 만드는 리스트 컴프리헨션이 파티션 역할을 합니다. 피벗 기준으로 작은 것/큰 것이 자동으로 나뉘죠!

    Step 2: 병합 정렬 구현하기¶

    def merge_sort(arr):
    if len(arr) <= 1:
        return arr

    mid = len(arr) // 2
    left = merge_sort(arr[:mid])    # 왼쪽 절반 정렬
    right = merge_sort(arr[mid:])   # 오른쪽 절반 정렬

    return merge(left, right)

def merge(left, right):
    """정렬된 두 리스트를 하나로 합친다"""
    result = []
    i, j = 0, 0

    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1

    # 남은 원소 추가
    result.extend(left[i:])
    result.extend(right[j:])
    return result

# 테스트
data = [5, 3, 8, 1, 2, 7, 4, 6]
print("정렬 전:", data)
print("정렬 후:", merge_sort(data))

    실행 결과: 

    정렬 전: [5, 3, 8, 1, 2, 7, 4, 6]
정렬 후: [1, 2, 3, 4, 5, 6, 7, 8]

    Step 3: 병합(merge) 함수 동작 직접 확인하기¶

    병합 과정을 눈으로 확인해 봅시다.

    def merge_verbose(left, right):
    """병합 과정을 출력하며 합친다"""
    result = []
    i, j = 0, 0
    print(f"  병합 시작: {left} + {right}")

    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1

    result.extend(left[i:])
    result.extend(right[j:])
    print(f"  병합 결과: {result}")
    return result

# 간단한 예시
merge_verbose([1, 5, 8], [2, 3, 7])

    실행 결과: 

      병합 시작: [1, 5, 8] + [2, 3, 7]
  병합 결과: [1, 2, 3, 5, 7, 8]

    양쪽 맨 앞을 비교하여 작은 것부터 꺼내는 과정이 핵심입니다.

    Step 4: 기본 정렬 vs 고급 정렬 성능 비교 실험 🧪¶

    14차시에서 배운 선택 정렬과 이번 장의 정렬을 데이터 크기를 늘려가며 비교합니다.

    import time
import random

def selection_sort(arr):
    arr = arr.copy()
    for i in range(len(arr)):
        min_idx = i
        for j in range(i + 1, len(arr)):
            if arr[j] < arr[min_idx]:
                min_idx = j
        arr[i], arr[min_idx] = arr[min_idx], arr[i]
    return arr

def measure_time(sort_func, data):
    start = time.time()
    sort_func(data)
    return round(time.time() - start, 4)

# 실험 실행
for n in [1000, 5000, 10000]:
    data = random.sample(range(n * 10), n)

    t_selection = measure_time(selection_sort, data)
    t_quick = measure_time(quick_sort, data)
    t_merge = measure_time(merge_sort, data)

    print(f"n={n:>6} | 선택정렬: {t_selection:.4f}초"
          f" | 퀵정렬: {t_quick:.4f}초"
          f" | 병합정렬: {t_merge:.4f}초")

    예상 실행 결과 (컴퓨터마다 다를 수 있음): 

    n=  1000 | 선택정렬: 0.0300초 | 퀵정렬: 0.0020초 | 병합정렬: 0.0025초
n=  5000 | 선택정렬: 0.7500초 | 퀵정렬: 0.0100초 | 병합정렬: 0.0130초
n= 10000 | 선택정렬: 3.0000초 | 퀵정렬: 0.0220초 | 병합정렬: 0.0270초

    🔥 데이터가 10배 늘면 선택 정렬은 100배 느려지고, 퀵/병합 정렬은 약 10~15배만 느려집니다. 이것이 O(n²)와 O(n log n)의 차이입니다!

    Step 5: 파이썬 내장 sorted()와도 비교하기¶

    for n in [1000, 5000, 10000]:
    data = random.sample(range(n * 10), n)

    t_quick = measure_time(quick_sort, data)
    t_merge = measure_time(merge_sort, data)
    t_builtin = measure_time(sorted, data)

    print(f"n={n:>6} | 퀵: {t_quick:.4f}초"
          f" | 병합: {t_merge:.4f}초"
          f" | sorted(): {t_builtin:.6f}초")

    💡 알아보기: 파이썬의 sorted()는 Tim Sort라는 알고리즘을 사용합니다. 병합 정렬과 삽입 정렬을 결합한 고급 알고리즘으로, C언어로 구현되어 있어 훨씬 빠릅니다. 우리가 직접 짠 코드보다 빠른 건 당연하니 좌절하지 마세요! 😄

    📝 전체 코드¶

    """
15장: 고급 정렬 - 퀵 정렬과 병합 정렬
아래 코드를 복사해서 바로 실행할 수 있습니다.
"""
import time
import random

# ── 퀵 정렬 ──
def quick_sort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[-1]
    left = [x for x in arr[:-1] if x <= pivot]
    right = [x for x in arr[:-1] if x > pivot]
    return quick_sort(left) + [pivot] + quick_sort(right)

# ── 병합 정렬 ──
def merge_sort(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])
    return merge(left, right)

def merge(left, right):
    result = []
    i, j = 0, 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result

# ── 선택 정렬 (비교용) ──
def selection_sort(arr):
    arr = arr.copy()
    for i in range(len(arr)):
        min_idx = i
        for j in range(i + 1, len(arr)):
            if arr[j] < arr[min_idx]:
                min_idx = j
        arr[i], arr[min_idx] = arr[min_idx], arr[i]
    return arr

# ── 성능 측정 ──
def measure_time(sort_func, data):
    start = time.time()
    sort_func(data)
    return round(time.time() - start, 4)

    심화 문제¶

    문제 4. 이미 정렬된 리스트 [1, 2, 3, 4, 5]에 퀵 정렬(피벗 = 마지막 원소)을 적용하면 어떤 문제가 생길까요? 시간 복잡도는 어떻게 되나요?

    정답 보기 피벗이 항상 최댓값이 되어, left에 나머지 전부가 들어가고 right는 비게 됩니다. - 1단계: left=[1,2,3,4], 피벗=5, right=[] - 2단계: left=[1,2,3], 피벗=4, right=[] - ... 한쪽으로만 치우치는 **최악의 경우**가 발생하여, 분할이 n단계나 필요합니다. 시간 복잡도는 **O(n²)** 이 됩니다. 이것이 퀵 정렬의 약점이며, 이를 방지하려면 피벗을 랜덤으로 고르거나 중간값을 사용합니다.

    import random

def quick_sort_random(arr):
    if len(arr) <= 1:
        return arr
    pivot_idx = random.randint(0, len(arr) - 1)
    pivot = arr[pivot_idx]
    rest = arr[:pivot_idx] + arr[pivot_idx + 1:]
    left = [x for x in rest if x <= pivot]
    right = [x for x in rest if x > pivot]
    return quick_sort_random(left) + [pivot] + quick_sort_random(right)
