    Chapter 20: 알고리즘 종합 정리와 프로젝트 설계¶

    Part 5 | [2권] 그래프 알고리즘과 프로젝트 — 마지막 차시

    🎯 이 장에서 배우는 것¶

    • 정렬·탐색·그래프 알고리즘 전체를 비교 정리하고 핵심 원리를 한 문장으로 요약할 수 있다
    • 실생활 문제를 분석하여 적절한 자료구조와 알고리즘을 선택할 수 있다
    • 진로 연계 프로젝트의 주제를 선정하고 구현 계획서를 작성할 수 있다
    • 프로젝트 핵심 기능 1개를 프로토타입으로 구현할 수 있다

    💡 왜 이걸 배우나요?¶

    여러분은 지금까지 19개 차시에 걸쳐 정렬, 탐색, 재귀, 그래프 등 다양한 알고리즘을 배웠습니다. 그런데 실제 문제를 만나면 이런 고민이 생깁니다.

    "이 문제에는 어떤 알고리즘을 써야 하지? 🤔"

    요리를 배울 때를 떠올려 보세요. 볶음, 찜, 튀김, 구이 등 개별 조리법을 배운 뒤, 마지막에 해야 할 일은 "오늘 저녁 메뉴에 어떤 조리법을 적용할지 결정하는 것"입니다. 이 장은 바로 그 메뉴 설계 단계입니다.

    20차시 전체를 하나의 지도로 정리하고, 그 지도를 들고 나만의 프로젝트를 설계해 봅시다. 이 과정이 알고리즘을 진짜 "내 것"으로 만드는 마지막 퍼즐 조각입니다. 🧩

    📚 핵심 개념¶

    개념 1: 알고리즘 종합 지도 — "문제 → 알고리즘 → 자료구조" 맵¶

    1) 비유로 시작

    병원에 가면 증상에 따라 진료과가 다릅니다. 열이 나면 내과, 뼈가 아프면 정형외과로 갑니다. 알고리즘도 마찬가지입니다. 문제의 유형을 먼저 파악하면, 어떤 알고리즘과 자료구조를 써야 하는지 자연스럽게 결정됩니다.

    2) 정확한 정의

    "문제 유형 → 적합한 알고리즘 → 필요한 자료구조"로 이어지는 매핑(mapping)을 알고리즘 선택 전략이라고 합니다.

    3) 예시로 확인 — 전체 알고리즘 종합 정리

    mindmap root((알고리즘 종합 지도)) 정렬 문제 버블 정렬 O(n²), 리스트 선택 정렬 O(n²), 리스트 삽입 정렬 O(n²), 리스트 병합 정렬 O(n log n), 리스트+재귀 퀵 정렬 O(n log n) 평균, 리스트+재귀 탐색 문제 선형 탐색 O(n), 리스트 이진 탐색 O(log n), 정렬된 리스트 그래프 문제 BFS 최단 경로(가중치 없음), 큐 DFS 연결 요소/경로 탐색, 스택/재귀 다익스트라 최단 경로(가중치 있음), 우선순위 큐 최적화 문제 그리디 탐욕적 선택, 정렬+힙 동적 프로그래밍 중복 부분문제, 배열/딕셔너리

    📌 정리하기: 문제를 만나면 ①유형 파악 → ②알고리즘 후보 선정 → ③자료구조 결정, 이 3단계를 거치세요.

    개념 2: 시간 복잡도 한눈에 비교¶

    1) 비유로 시작

    택배 회사를 고를 때 "배송 속도"와 "비용"을 비교하듯, 알고리즘도 시간 복잡도(속도)와 공간 복잡도(메모리)를 비교하여 선택합니다.

    2) 핵심 비교

    graph LR A["O(1)"] -->|"빠름"| B["O(log n)"] B --> C["O(n)"] C --> D["O(n log n)"] D --> E["O(n²)"] E -->|"느림"| F["O(2ⁿ)"]
    • O(1): 딕셔너리 조회, 배열 인덱스 접근
    • O(log n): 이진 탐색
    • O(n): 선형 탐색
    • O(n log n): 병합 정렬, 퀵 정렬(평균)
    • O(n²): 버블·선택·삽입 정렬
    • O(2ⁿ): 최적화 없는 피보나치 재귀

    3) 예시로 확인

    데이터 1,000개일 때 연산 횟수 체감:

    • O(n) → 약 1,000번
    • O(n log n) → 약 10,000번
    • O(n²) → 약 1,000,000번 (1,000배 차이!)

    💡 알아보기: 데이터가 적으면 O(n²)도 괜찮지만, 데이터가 커질수록 O(n log n) 이하의 알고리즘을 선택하는 것이 중요합니다.

    개념 3: 실생활 문제 분석 프레임워크¶

    1) 비유로 시작

    의사가 환자를 진단할 때 "문진 → 검사 → 처방" 순서를 밟듯, 프로젝트 설계도 체계적인 분석 절차가 필요합니다.

    2) 정확한 정의 — 5단계 분석 프레임워크

    flowchart TD A["① 문제 정의<br/>무엇을 해결할 것인가?"] --> B["② 데이터 파악<br/>입력은 무엇이고 얼마나 큰가?"] B --> C["③ 알고리즘 선택<br/>어떤 전략이 적합한가?"] C --> D["④ 자료구조 결정<br/>데이터를 어떻게 저장할 것인가?"] D --> E["⑤ 구현 및 검증<br/>코드로 옮기고 테스트"]

    3) 예시로 확인 — "학교 축제 부스 최적 동선"

    • ① 문제 정의: 10개 부스를 모두 방문하는 가장 짧은 동선 찾기
    • ② 데이터 파악: 부스 위치(좌표), 부스 간 거리 → 그래프로 표현 가능
    • ③ 알고리즘 선택: 그래프 최단 경로 → 다익스트라 또는 BFS
    • ④ 자료구조 결정: 인접 리스트(딕셔너리) + 우선순위 큐
    • ⑤ 구현: NetworkX로 그래프 구축 후 경로 탐색

    개념 4: 프로젝트 계획서 작성법¶

    1) 비유로 시작

    건축가가 집을 짓기 전에 설계도를 그리듯, 프로그래밍 프로젝트도 계획서가 먼저입니다. 설계도 없이 짓기 시작하면 벽이 삐뚤어집니다. 🏗️

    2) 계획서에 포함할 7가지 항목

    • 프로젝트 제목: 한 문장으로 명확하게
    • 문제 설명: 어떤 문제를 왜 해결하는가
    • 사용할 알고리즘: 근거와 함께 명시
    • 사용할 자료구조: 왜 이 구조가 적합한지
    • 핵심 기능 목록: 3개 이내로 핵심만
    • 구현 도구: Python, NetworkX 등
    • 예상 결과물: 출력 형태(텍스트, 시각화 등)

    3) 프로젝트 주제 영감 3선

    flowchart LR subgraph 주제1["🚌 교통 최적 경로"] A1["다익스트라 알고리즘"] A2["가중치 그래프"] end subgraph 주제2["🎬 콘텐츠 추천"] B1["BFS/유사도 탐색"] B2["인접 리스트"] end subgraph 주제3["🦠 전염병 확산"] C1["BFS 시뮬레이션"] C2["그래프 + 큐"] end

    🔨 따라하기: 전염병 확산 시뮬레이션 프로젝트¶

    실제로 5단계 분석 프레임워크를 적용하여 프로젝트를 설계하고, 핵심 기능 1개를 프로토타입으로 구현합니다.

    Step 1: 문제 정의¶

    "10명의 학생이 연결된 친구 네트워크에서, 한 명이 감염되었을 때 감염이 어떻게 퍼지는지 시뮬레이션한다."

    # 문제를 코드 주석으로 정리하는 습관을 기르세요
# 문제: 친구 네트워크에서 감염 확산 과정 시뮬레이션
# 입력: 친구 관계(그래프), 최초 감염자
# 출력: 단계별 감염자 목록

    Step 2: 데이터 파악 및 그래프 구축¶

    학생 간의 친구 관계를 그래프로 표현합니다.

    import networkx as nx

# 친구 네트워크 생성
G = nx.Graph()
G.add_nodes_from(range(1, 11))  # 학생 1~10

# 친구 관계 (간선)
friendships = [
    (1, 2), (1, 3), (2, 4), (2, 5),
    (3, 6), (4, 7), (5, 7), (5, 8),
    (6, 9), (8, 10), (9, 10)
]
G.add_edges_from(friendships)

print(f"학생 수: {G.number_of_nodes()}")
print(f"친구 관계 수: {G.number_of_edges()}")

    Step 3: 알고리즘 선택 — BFS 기반 확산¶

    감염은 가까운 친구부터 순서대로 퍼집니다. 이것은 BFS(너비 우선 탐색)와 정확히 같은 패턴입니다!

    flowchart TD Q["왜 BFS인가?"] Q --> R1["감염은 단계별로 퍼짐"] Q --> R2["가까운 접촉자부터 감염"] Q --> R3["BFS는 레벨 단위 탐색"] R1 --> ANSWER["BFS가 최적!"] R2 --> ANSWER R3 --> ANSWER

    Step 4: 핵심 기능 구현 — 확산 시뮬레이션¶

    from collections import deque

def simulate_spread(graph, patient_zero):
    """BFS 기반 감염 확산 시뮬레이션"""
    infected = {patient_zero}       # 감염된 학생 집합
    queue = deque([(patient_zero, 0)])  # (학생, 감염 단계)
    spread_log = {0: [patient_zero]}    # 단계별 감염 기록

    while queue:
        current, step = queue.popleft()
        next_step = step + 1

        for neighbor in graph.neighbors(current):
            if neighbor not in infected:
                infected.add(neighbor)
                queue.append((neighbor, next_step))

                # 단계별 기록
                if next_step not in spread_log:
                    spread_log[next_step] = []
                spread_log[next_step].append(neighbor)

    return spread_log, infected

# 실행: 학생 1이 최초 감염자
log, all_infected = simulate_spread(G, 1)

print("=== 감염 확산 시뮬레이션 ===")
for step in sorted(log.keys()):
    print(f"  단계 {step}: 학생 {log[step]} 감염")
print(f"\n최종 감염자: {sorted(all_infected)}")
print(f"총 {len(all_infected)}명 감염")

    Step 5: 결과 시각화¶

    import matplotlib.pyplot as plt

def visualize_spread(graph, spread_log):
    """감염 확산을 색상으로 시각화"""
    pos = nx.spring_layout(graph, seed=42)

    # 단계별 색상 지정
    color_map = {}
    colors = ['red', 'orange', 'yellow', 'lightgreen', 'lightblue']
    for step, students in spread_log.items():
        for s in students:
            color_map[s] = colors[min(step, len(colors)-1)]

    node_colors = [color_map.get(node, 'gray') for node in graph.nodes()]

    plt.figure(figsize=(8, 6))
    nx.draw(graph, pos, with_labels=True, 
            node_color=node_colors, node_size=500,
            font_size=14, font_weight='bold',
            edge_color='gray', width=2)
    plt.title("전염병 확산 시뮬레이션 결과", fontsize=16)
    plt.tight_layout()
    plt.savefig("spread_simulation.png", dpi=100)
    plt.show()

visualize_spread(G, log)

    📝 전체 코드¶

    아래는 위 따라하기의 전체 코드를 하나로 합친 것입니다. 복사하여 바로 실행할 수 있습니다.

    import networkx as nx
from collections import deque

# ───────────────────────────────────
# 1. 친구 네트워크 구축
# ───────────────────────────────────
G = nx.Graph()
G.add_nodes_from(range(1, 11))

friendships = [
    (1, 2), (1, 3), (2, 4), (2, 5),
    (3, 6), (4, 7), (5, 7), (5, 8),
    (6, 9), (8, 10), (9, 10)
]
G.add_edges_from(friendships)

# ───────────────────────────────────
# 2. BFS 감염 확산 시뮬레이션
# ───────────────────────────────────
def simulate_spread(graph, patient_zero):
    infected = {patient_zero}
    queue = deque([(patient_zero, 0)])
    spread_log = {0: [patient_zero]}

    while queue:
        current, step = queue.popleft()
        next_step = step + 1

        for neighbor in graph.neighbors(current):
            if neighbor not in infected:
                infected.add(neighbor)
                queue.append((neighbor, next_step))
                if next_step not in spread_log:
                    spread_log[next_step] = []
                spread_log[next_step].append(neighbor)

    return spread_log, infected

log, all_infected = simulate_spread(G, 1)

# ───────────────────────────────────
# 3. 결과 출력
# ───────────────────────────────────
print("🦠 감염 확산 시뮬레이션 결과")
print("=" * 35)
for step in sorted(log.keys()):
    names = ", ".join(f"학생{s}" for s in log[step])
    print(f"  단계 {step}: {names}")

print(f"\n📊 총 감염자 수: {len(all_infected)}명")
print(f"📊 감염자 목록: {sorted(all_infected)}")

# ───────────────────────────────────
# 4. 알고리즘 선택 근거 출력
# ───────────────────────────────────
print("\n💡 왜 BFS를 선택했나?")
print("  → 감염은 접촉자(이웃 노드)부터 단계적으로 퍼짐")
print("  → BFS는 레벨(단계) 단위로 탐색하므로 확산 모델에 최적")

    ⚠️ 자주 하는 실수¶

    실수 1: 문제 유형을 분석하지 않고 바로 코딩 시작

    "일단 코드부터 짜볼게요!" → ❌

    알고리즘 선택이 잘못되면 나중에 전부 다시 짜야 합니다. 항상 5단계 프레임워크(문제 정의 → 데이터 파악 → 알고리즘 선택 → 자료구조 결정 → 구현)를 먼저 거치세요.

    실수 2: 모든 것을 한 번에 구현하려고 함

    "시각화도 하고, 통계도 내고, UI도 만들고..." → ❌

    프로젝트는 핵심 기능 1개부터 동작하게 만든 뒤 확장하세요. 이것을 프로토타입(prototype) 우선 개발이라고 합니다. 위 실습에서도 감염 확산 로직 → 출력 → 시각화 순서로 점진적으로 만들었습니다.

    실수 3: 알고리즘 특성을 무시한 선택

    "다익스트라가 멋있으니까 이걸 쓸래요!" → ❌

    가중치 없는 그래프에 다익스트라를 쓰면 불필요하게 복잡합니다. 아래를 기억하세요:

    • 가중치 없는 최단 경로 → BFS
    • 가중치 있는 최단 경로 → 다익스트라
    • 모든 경로 탐색 / 연결 확인 → DFS
    • 정렬이 필요하고 데이터가 큼 → 병합 정렬 또는 퀵 정렬

    🔑 생각해보기: "가장 좋은 알고리즘"은 없습니다. "이 문제에 가장 적합한 알고리즘"이 있을 뿐입니다.

    심화 문제 (도전! 🔥)¶

    Q4. 아래 코드의 simulate_spread 함수를 수정하여, 감염 확률 70% (친구와 접촉해도 30% 확률로 감염되지 않음)를 적용한 버전을 만들어 보세요.

    힌트 `random.random()`은 0~1 사이의 랜덤 값을 반환합니다. 이 값이 0.7 이하일 때만 감염되도록 조건을 추가하세요.
    정답 코드 
    import random
from collections import deque

def simulate_spread_prob(graph, patient_zero, prob=0.7):
    random.seed(42)  # 재현 가능하도록 시드 고정
    infected = {patient_zero}
    queue = deque([(patient_zero, 0)])
    spread_log = {0: [patient_zero]}

    while queue:
        current, step = queue.popleft()
        next_step = step + 1

        for neighbor in graph.neighbors(current):
            if neighbor not in infected:
                if random.random() <= prob:  # 70% 확률로 감염
                    infected.add(neighbor)
                    queue.append((neighbor, next_step))
                    if next_step not in spread_log:
                        spread_log[next_step] = []
                    spread_log[next_step].append(neighbor)

    return spread_log, infected
