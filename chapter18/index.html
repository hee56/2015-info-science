    Chapter 18: 최단 경로 알고리즘 - 네비게이션의 원리¶

    Part 5 | [2권] 그래프 알고리즘과 프로젝트

    🎯 이 장에서 배우는 것¶

    • 가중치 그래프가 무엇인지 설명하고, 현실 문제와 연결할 수 있다
    • 다익스트라 알고리즘의 동작 원리를 단계별로 추적할 수 있다
    • 우선순위 큐(힙)를 활용한 다익스트라 알고리즘을 파이썬으로 구현할 수 있다
    • 가중치 그래프에서 최단 경로를 구하고, 경로를 역추적할 수 있다

    💡 왜 이걸 배우나요?¶

    스마트폰에서 네비게이션 앱을 켜고 "가장 빠른 길"을 검색해본 적 있나요? 앱은 수만 개의 교차로와 도로 중에서 단 몇 초 만에 최적의 경로를 찾아줍니다. 이 마법 같은 일의 핵심에 바로 다익스트라(Dijkstra) 알고리즘이 있습니다.

    최단 경로 알고리즘은 네비게이션뿐 아니라 다양한 곳에서 활약합니다.

    • 🗺️ 지도 앱: 출발지에서 목적지까지 최단/최소 시간 경로
    • 🌐 인터넷 라우팅: 데이터 패킷이 가장 빠른 경로로 전달
    • 🎮 게임 AI: 적 캐릭터가 플레이어에게 다가오는 경로 계산
    • 🚇 대중교통 앱: 최소 환승, 최소 시간 경로 안내

    이 장을 마치면, 여러분도 자신만의 간단한 네비게이션을 만들 수 있게 됩니다!

    📚 핵심 개념¶

    개념 1: 가중치 그래프 — 거리가 있는 지도¶

    🔍 비유로 시작

    이전 장에서 배운 그래프는 "연결되어 있다/없다"만 표현했습니다. 마치 지도에서 도시 사이에 도로가 있는지 없는지만 표시한 것과 같죠. 하지만 실제 네비게이션은 도로의 거리(km) 또는 소요 시간(분)도 알아야 합니다. 이렇게 간선(edge)에 숫자(가중치)가 붙은 그래프를 가중치 그래프(Weighted Graph)라고 합니다.

    📐 정확한 정의

    • 가중치(Weight): 간선에 부여된 숫자값. 거리, 시간, 비용 등을 나타냄
    • 가중치 그래프: 모든 간선에 가중치가 있는 그래프
    • 최단 경로: 출발 정점에서 도착 정점까지 가중치 합이 최소인 경로

    ✏️ 예시로 확인

    다섯 개 도시와 도로를 가중치 그래프로 표현해봅시다.

    graph LR A["서울"] -- "30분" --- B["수원"] A -- "60분" --- C["인천"] B -- "20분" --- C B -- "50분" --- D["대전"] C -- "40분" --- D D -- "90분" --- E["부산"] B -- "120분" --- E

    서울에서 부산까지 가는 경로가 여러 개 있습니다.

    • 경로 1: 서울 → 수원 → 부산 = 30 + 120 = 150분
    • 경로 2: 서울 → 수원 → 대전 → 부산 = 30 + 50 + 90 = 170분
    • 경로 3: 서울 → 인천 → 대전 → 부산 = 60 + 40 + 90 = 190분
    • 경로 4: 서울 → 수원 → 인천 → 대전 → 부산 = 30 + 20 + 40 + 90 = 180분

    경로 1이 최단 경로입니다. 하지만 도시가 수백 개라면? 모든 경로를 일일이 비교할 수 없습니다. 그래서 체계적인 알고리즘이 필요합니다.

    개념 2: 다익스트라 알고리즘 — 핵심 아이디어¶

    🔍 비유로 시작

    다익스트라 알고리즘을 "물이 퍼져나가는 것"에 비유할 수 있습니다.

    출발점에 물을 부으면, 물은 가장 가까운 곳부터 차례대로 퍼져나갑니다. 좁은 수로(짧은 거리)를 통해 먼저 도달한 지점이 확정되고, 그 지점에서 다시 물이 퍼져나갑니다. 이미 물이 찬 지점에는 더 이상 물을 보내지 않습니다.

    📐 정확한 정의

    다익스트라 알고리즘의 핵심 규칙 세 가지:

    • 규칙 1 — 초기화: 출발점의 거리는 0, 나머지 모든 정점의 거리는 ∞(무한대)
    • 규칙 2 — 선택: 아직 방문하지 않은 정점 중 거리가 가장 작은 정점을 선택하여 방문 확정
    • 규칙 3 — 갱신(Relaxation): 확정된 정점의 이웃을 살펴보고, 더 짧은 경로가 발견되면 거리를 업데이트

    💡 알아보기: "Relaxation(완화)"이란 이름은 고무줄을 떠올리면 됩니다. 팽팽하게 늘어난 거리(∞)를 더 짧은 거리로 느슨하게 줄여주는 과정입니다.

    ✏️ 예시로 확인 — 단계별 추적

    아래 그래프에서 A → E의 최단 경로를 찾아봅시다.

    graph LR A -- "4" --- B A -- "2" --- C B -- "3" --- D C -- "1" --- B C -- "5" --- D D -- "1" --- E

    🔄 단계별 진행

    [초기 상태] - A = 0 / B = ∞ / C = ∞ / D = ∞ / E = ∞ - 방문 확정: 없음

    [Step 1] 미방문 중 최소 거리: A(0) → 방문 확정! - A의 이웃 확인: B(0+4=4), C(0+2=2) - B = min(∞, 4) = 4 / C = min(∞, 2) = 2 - 현재 상태: A = ~~0~~ / B = 4 / C = 2 / D = ∞ / E = ∞

    [Step 2] 미방문 중 최소 거리: C(2) → 방문 확정! - C의 이웃 확인: B(2+1=3), D(2+5=7) - B = min(4, 3) = 3 ⬅️ 더 짧은 경로 발견! / D = min(∞, 7) = 7 - 현재 상태: A = ~~0~~ / B = 3 / C = ~~2~~ / D = 7 / E = ∞

    [Step 3] 미방문 중 최소 거리: B(3) → 방문 확정! - B의 이웃 확인: D(3+3=6) - D = min(7, 6) = 6 ⬅️ 더 짧은 경로 발견! - 현재 상태: A = ~~0~~ / B = ~~3~~ / C = ~~2~~ / D = 6 / E = ∞

    [Step 4] 미방문 중 최소 거리: D(6) → 방문 확정! - D의 이웃 확인: E(6+1=7) - E = min(∞, 7) = 7 - 현재 상태: A = ~~0~~ / B = ~~3~~ / C = ~~2~~ / D = ~~6~~ / E = 7

    [Step 5] 미방문 중 최소 거리: E(7) → 방문 확정! ✅

    결과: A에서 E까지의 최단 거리는 7, 경로는 A → C → B → D → E

    🤔 생각해보기: Step 2에서 B의 거리가 4에서 3으로 줄었습니다. "서울 → 수원"보다 "서울 → 인천 → 수원"이 더 빠른 것처럼, 직행이 항상 최선은 아닙니다!

    개념 3: 우선순위 큐(힙) — 효율의 비결¶

    🔍 비유로 시작

    다익스트라 알고리즘에서 매번 "미방문 정점 중 거리가 가장 작은 것"을 찾아야 합니다. 정점이 10개면 괜찮지만, 10만 개라면? 매번 전체를 훑어보는 것은 비효율적입니다.

    우선순위 큐(Priority Queue)는 마치 응급실 대기 시스템과 같습니다. 환자가 도착한 순서가 아니라 긴급도 순서로 진료합니다. 새 환자가 와도, 자동으로 긴급도에 맞는 위치에 배치됩니다.

    📐 정확한 정의

    • 우선순위 큐: 넣을 때는 아무 순서로, 꺼낼 때는 항상 가장 작은(또는 큰) 값이 나오는 자료구조
    • 힙(Heap): 우선순위 큐를 구현하는 대표적인 자료구조 (Chapter 13에서 학습)
    • 파이썬의 heapq 모듈이 최소 힙을 제공 → 가장 작은 거리가 먼저 나옴

    ✏️ 예시로 확인

    import heapq

# 빈 힙 생성
pq = []

# (거리, 정점) 형태로 삽입
heapq.heappush(pq, (4, 'B'))
heapq.heappush(pq, (2, 'C'))
heapq.heappush(pq, (7, 'D'))

# 가장 작은 거리부터 꺼냄
print(heapq.heappop(pq))  # (2, 'C') ← 최소!
print(heapq.heappop(pq))  # (4, 'B')
print(heapq.heappop(pq))  # (7, 'D')

    💡 알아보기: heapq에 튜플을 넣으면 첫 번째 원소를 기준으로 정렬됩니다. 그래서 (거리, 정점) 순서로 넣으면 거리가 가장 짧은 것이 먼저 나옵니다.

    시간 복잡도 비교

    graph TB subgraph 리스트["📋 리스트로 최소값 찾기"] L1["매번 전체 탐색"] L2["O(V²)"] L1 --> L2 end subgraph 힙["⚡ 힙으로 최소값 찾기"] H1["자동 정렬"] H2["O((V+E) log V)"] H1 --> H2 end

    정점(V)이 많아질수록 힙을 사용한 구현이 압도적으로 빠릅니다.

    개념 4: 경로 역추적 — "어디를 거쳐왔는가?"¶

    🔍 비유로 시작

    다익스트라 알고리즘은 "최단 거리"는 알려주지만, 기본적으로 "어떤 경로로 갔는지"는 알려주지 않습니다. 네비게이션이 "30분 걸립니다"만 말하고 경로를 안 보여주면 쓸모없겠죠?

    해결 방법은 간단합니다. 각 정점마다 "누가 나를 업데이트해줬는지"를 기록하면 됩니다. 마치 빵 부스러기를 흘리며 걸어간 헨젤과 그레텔처럼, 왔던 길을 되짚을 수 있습니다.

    📐 정확한 정의

    • 이전 정점(previous) 딕셔너리: 각 정점이 최단 거리로 갱신될 때, 어떤 정점에서 왔는지 기록
    • 역추적: 도착점에서 시작하여 previous를 따라 출발점까지 거슬러 올라감

    ✏️ 예시로 확인

    앞의 예시에서 previous 기록:

    • E의 이전 → D (D에서 E로 갱신)
    • D의 이전 → B (B에서 D로 갱신)
    • B의 이전 → C (C에서 B로 갱신)
    • C의 이전 → A (A에서 C로 갱신)

    역추적: E ← D ← B ← C ← A → 뒤집으면 A → C → B → D → E ✅

    🔨 따라하기¶

    Step 1: 가중치 그래프 만들기¶

    딕셔너리로 가중치 그래프를 표현합니다. 각 정점의 이웃을 (이웃정점, 가중치) 튜플의 리스트로 저장합니다.

    # 가중치 그래프 (인접 리스트 방식)
graph = {
    'A': [('B', 4), ('C', 2)],
    'B': [('A', 4), ('C', 1), ('D', 3)],
    'C': [('A', 2), ('B', 1), ('D', 5)],
    'D': [('B', 3), ('C', 5), ('E', 1)],
    'E': [('D', 1)]
}

    양방향 도로이므로, A→B가 4이면 B→A도 4로 양쪽 다 기록합니다.

    Step 2: 기본 다익스트라 구현 (리스트 방식)¶

    먼저 힙 없이, 개념을 그대로 코드로 옮겨봅시다.

    def dijkstra_basic(graph, start):
    # 1. 초기화
    distances = {node: float('inf') for node in graph}
    distances[start] = 0
    visited = set()

    while len(visited) < len(graph):
        # 2. 미방문 중 최소 거리 정점 선택
        min_dist = float('inf')
        min_node = None
        for node in graph:
            if node not in visited and distances[node] < min_dist:
                min_dist = distances[node]
                min_node = node

        if min_node is None:
            break

        # 3. 방문 확정
        visited.add(min_node)

        # 4. 이웃 거리 갱신 (Relaxation)
        for neighbor, weight in graph[min_node]:
            new_dist = distances[min_node] + weight
            if new_dist < distances[neighbor]:
                distances[neighbor] = new_dist

    return distances

    Step 3: 힙을 활용한 효율적 구현¶

    이제 heapq를 사용하여 "미방문 중 최소 거리 정점"을 빠르게 찾겠습니다.

    import heapq

def dijkstra_heap(graph, start):
    distances = {node: float('inf') for node in graph}
    distances[start] = 0
    pq = [(0, start)]  # (거리, 정점) 형태의 힙

    while pq:
        current_dist, current_node = heapq.heappop(pq)

        # 이미 더 짧은 거리로 처리된 정점이면 건너뛰기
        if current_dist > distances[current_node]:
            continue

        # 이웃 거리 갱신
        for neighbor, weight in graph[current_node]:
            new_dist = current_dist + weight
            if new_dist < distances[neighbor]:
                distances[neighbor] = new_dist
                heapq.heappush(pq, (new_dist, neighbor))

    return distances

    🤔 생각해보기: if current_dist > distances[current_node]: continue가 왜 필요할까요? 힙에 같은 정점이 여러 번 들어갈 수 있습니다. 이전에 넣은 (더 긴 거리의) 항목이 나오면 무시하는 것입니다.

    Step 4: 경로 역추적 기능 추가¶

    최단 거리뿐 아니라 실제 경로도 알려주는 완성판입니다.

    import heapq

def dijkstra_with_path(graph, start):
    distances = {node: float('inf') for node in graph}
    distances[start] = 0
    previous = {node: None for node in graph}  # 경로 역추적용
    pq = [(0, start)]

    while pq:
        current_dist, current_node = heapq.heappop(pq)

        if current_dist > distances[current_node]:
            continue

        for neighbor, weight in graph[current_node]:
            new_dist = current_dist + weight
            if new_dist < distances[neighbor]:
                distances[neighbor] = new_dist
                previous[neighbor] = current_node  # ← 핵심!
                heapq.heappush(pq, (new_dist, neighbor))

    return distances, previous

def get_path(previous, start, end):
    """도착점에서 출발점까지 역추적"""
    path = []
    current = end
    while current is not None:
        path.append(current)
        current = previous[current]
    path.reverse()  # 뒤집어서 출발→도착 순서로

    if path[0] == start:
        return path
    return []  # 경로 없음

    import heapq

def dijkstra_with_path(graph, start):
    """다익스트라 알고리즘 (힙 기반, 경로 역추적 포함)"""
    # 초기화
    distances = {node: float('inf') for node in graph}
    distances[start] = 0
    previous = {node: None for node in graph}
    pq = [(0, start)]  # 최소 힙: (거리, 정점)

    while pq:
        current_dist, current_node = heapq.heappop(pq)

        # 이미 처리된 더 짧은 거리가 있으면 건너뛰기
        if current_dist > distances[current_node]:
            continue

        # 이웃 정점 거리 갱신
        for neighbor, weight in graph[current_node]:
            new_dist = current_dist + weight
            if new_dist < distances[neighbor]:
                distances[neighbor] = new_dist
                previous[neighbor] = current_node
                heapq.heappush(pq, (new_dist, neighbor))

    return distances, previous


def get_path(previous, start, end):
    """도착점에서 출발점까지 역추적하여 경로 반환"""
    path = []
    current = end
    while current is not None:
        path.append(current)
        current = previous[current]
    path.reverse()

    if path[0] == start:
        return path
    return []
