    Chapter 02. 리스트와 배열 - 데이터를 나란히 줄 세우기¶

    🎯 이 장에서 배우는 것¶

    • 배열과 리스트의 개념을 이해하고, 파이썬 리스트의 내부 동작 원리를 설명할 수 있다
    • 인덱싱을 활용하여 리스트의 원소에 접근하고 수정할 수 있다
    • 삽입·삭제·탐색 연산을 직접 구현하고 각 연산의 시간복잡도를 구분할 수 있다
    • 실험을 통해 리스트 연산의 효율성을 비교하고, 상황에 맞는 연산을 선택할 수 있다

    💡 왜 이걸 배우나요?¶

    프로그래밍에서 가장 많이 하는 일은 여러 개의 데이터를 다루는 것입니다.

    학생 30명의 점수를 저장한다고 생각해 보세요. 변수를 30개 만들 건가요?

    score1 = 85
score2 = 92
score3 = 78
# ... score30까지? 😱

    이건 너무 비효율적입니다. 리스트(list) 를 사용하면 단 한 줄이면 됩니다.

    scores = [85, 92, 78, 95, 88, ...]  # 데이터를 나란히 줄 세우기!

    리스트는 파이썬에서 가장 기본이 되는 자료구조입니다. 이번 장에서는 리스트가 내부적으로 어떻게 동작하는지, 그리고 어떤 연산이 빠르고 어떤 연산이 느린지를 직접 실험하며 배워보겠습니다.

    📚 핵심 개념¶

    개념 1: 배열과 리스트 — 영화관 좌석 비유¶

    🎬 비유로 시작하기

    영화관 좌석을 떠올려 보세요. 좌석은 일렬로 나란히 배치되어 있고, 각 좌석에는 번호가 붙어 있습니다. "A열 3번 좌석"이라고 하면 바로 그 자리를 찾아갈 수 있죠.

    graph LR subgraph "🎬 영화관 좌석 (배열의 비유)" S0["좌석 0번<br/>👤 철수"] S1["좌석 1번<br/>👤 영희"] S2["좌석 2번<br/>👤 민수"] S3["좌석 3번<br/>👤 지은"] S4["좌석 4번<br/>🪑 빈자리"] end S0 --- S1 --- S2 --- S3 --- S4

    배열(Array) 이 바로 이런 구조입니다.

    • 데이터를 연속된 메모리 공간에 나란히 저장합니다
    • 각 칸에는 인덱스(index) 라는 번호가 붙어 있습니다
    • 번호만 알면 즉시 해당 데이터에 접근할 수 있습니다

    📖 정확한 정의

    배열(Array): 같은 종류의 데이터를 연속된 메모리 공간에 순서대로 저장하는 자료구조. 인덱스를 사용하여 임의의 위치에 즉시 접근(O(1))할 수 있다.

    파이썬에서는 배열 대신 더 유연한 리스트(list) 를 제공합니다. 파이썬 리스트는 내부적으로 동적 배열(Dynamic Array) 로 구현되어 있어서, 크기가 자동으로 늘어나고 다양한 타입의 데이터도 함께 저장할 수 있습니다.

    💻 예시로 확인

    # 파이썬 리스트 생성
seats = ["철수", "영희", "민수", "지은"]

# 인덱스로 바로 접근 — 0번부터 시작!
print(seats[0])  # 철수
print(seats[2])  # 민수

# 길이 확인
print(len(seats))  # 4

    📌 알아보기: 파이썬의 인덱스는 0부터 시작합니다. 첫 번째 원소는 [0], 두 번째는 [1]입니다. 이것은 "메모리 시작 위치로부터의 거리"를 의미하기 때문입니다.

    개념 2: 리스트의 핵심 연산 — 삽입, 삭제, 탐색¶

    리스트에서 수행할 수 있는 핵심 연산 세 가지를 영화관 비유로 이해해 봅시다.

    🔹 삽입 (Insert)

    영화가 시작된 후 늦게 온 친구가 중간 좌석에 앉으려면? 그 자리부터 뒤에 있는 모든 사람이 한 칸씩 옆으로 이동해야 합니다. 하지만 맨 끝 빈자리에 앉는다면? 아무도 움직일 필요가 없습니다!

    graph TB subgraph "맨 뒤에 추가 (append) — 빠름 ⚡" A1["철수"] --> A2["영희"] --> A3["민수"] --> A4["✨ 새 친구"] end subgraph "중간에 삽입 (insert) — 느림 🐢" B1["철수"] --> B2["✨ 새 친구"] --> B3["영희 →"] --> B4["민수 →"] end

    🔹 삭제 (Delete)

    중간에 앉은 사람이 나가면? 빈자리를 메우기 위해 뒤의 사람들이 앞으로 한 칸씩 이동합니다. 맨 끝 사람이 나가면? 아무도 움직일 필요가 없습니다!

    🔹 탐색 (Search)

    "민수가 몇 번 좌석에 앉아있지?" → 0번부터 하나씩 확인해야 합니다. 이것을 순차 탐색(Linear Search) 이라고 합니다.

    seats = ["철수", "영희", "민수", "지은"]

# 삽입 연산
seats.append("수빈")          # 맨 뒤에 추가 → 빠름!
seats.insert(1, "하준")       # 1번 위치에 삽입 → 뒤의 원소가 밀림

# 삭제 연산
seats.pop()                   # 맨 뒤 삭제 → 빠름!
seats.pop(0)                  # 맨 앞 삭제 → 뒤의 원소가 당겨짐
del seats[1]                  # 1번 인덱스 삭제

# 탐색 연산
idx = seats.index("민수")     # "민수"가 몇 번째인지 찾기
print("민수" in seats)        # 포함 여부 확인 → True/False

    개념 3: 시간복잡도 — 연산이 얼마나 빠른가?¶

    ⏰ 비유로 시작하기

    100명이 앉은 영화관에서 맨 앞에 한 명을 끼워넣으려면 99명이 이동해야 합니다. 1000명이면? 999명이 이동합니다. 사람 수(n)가 늘어날수록 이동 횟수도 비례하여 늘어납니다.

    📖 정확한 정의

    시간복잡도(Time Complexity): 데이터의 개수(n)에 따라 연산에 걸리는 시간이 어떻게 변하는지를 나타내는 척도. 빅오(Big-O) 표기법으로 표현한다.

    핵심적인 두 가지만 기억하세요.

    • O(1) — "상수 시간": 데이터가 아무리 많아도 항상 일정한 시간이 걸림 (예: 인덱스 접근)
    • O(n) — "선형 시간": 데이터 개수에 비례하여 시간이 늘어남 (예: 중간 삽입, 순차 탐색)
    graph LR subgraph "파이썬 리스트 주요 연산의 시간복잡도" direction TB FAST["⚡ O(1) — 빠른 연산"] SLOW["🐢 O(n) — 느린 연산"] end FAST --- F1["인덱스 접근: list[i]"] FAST --- F2["맨 뒤 추가: append()"] FAST --- F3["맨 뒤 삭제: pop()"] SLOW --- S1["중간/맨앞 삽입: insert()"] SLOW --- S2["중간/맨앞 삭제: pop(i)"] SLOW --- S3["원소 탐색: in, index()"]

    💡 생각해보기: 왜 맨 뒤 연산은 빠르고 맨 앞 연산은 느릴까요? 배열은 연속된 공간에 데이터를 저장하기 때문에, 중간이나 앞에서 변화가 생기면 나머지 원소들을 전부 이동시켜야 하기 때문입니다.

    개념 4: 동적 배열 — 리스트는 어떻게 크기가 늘어나는가?¶

    📦 비유로 시작하기

    택배 상자에 물건을 넣고 있다고 상상하세요. 상자가 꽉 차면 더 큰 상자를 가져와서 기존 물건을 모두 옮기고, 새 물건을 추가합니다. 파이썬 리스트도 이와 같습니다.

    📖 정확한 정의

    동적 배열(Dynamic Array): 내부 배열이 가득 차면 더 큰 배열을 새로 할당하고 기존 데이터를 복사하는 방식으로 자동 확장되는 배열. 파이썬 리스트는 보통 현재 크기의 약 1.125배로 확장한다.

    import sys

data = []
for i in range(20):
    data.append(i)
    print(f"길이: {len(data):2d}, 내부 메모리 크기: {sys.getsizeof(data)} bytes")

    실행하면 길이가 1씩 늘어나는데, 메모리 크기는 계단식으로 늘어나는 것을 볼 수 있습니다. 이것이 바로 동적 배열이 미리 여유 공간을 확보하는 모습입니다.

    📌 알아보기: append()가 평균적으로 O(1)인 이유는 대부분의 경우 여유 공간에 바로 넣기만 하면 되고, 가끔 확장이 필요할 때만 O(n)이 걸리기 때문입니다. 이를 분할 상환 분석(Amortized Analysis) 이라고 하며, 평균 O(1)이라 표현합니다.

    🔨 따라하기¶

    파이썬 에디터(IDLE, VS Code 등)를 열고 직접 따라해 보세요!

    Step 1: 리스트 생성과 인덱싱¶

    # 학생 이름 리스트 생성
students = ["김철수", "이영희", "박민수", "정지은", "최하준"]

# 인덱스로 접근 (0번부터 시작!)
print(students[0])     # 김철수
print(students[3])     # 정지은

# 음수 인덱스: 뒤에서부터 접근
print(students[-1])    # 최하준 (마지막)
print(students[-2])    # 정지은 (뒤에서 두 번째)

# 슬라이싱: 범위로 접근
print(students[1:3])   # ['이영희', '박민수'] (1번 이상 3번 미만)

    직접 실행해 보고, 인덱스를 바꿔가며 결과를 예측해 보세요.

    Step 2: 삽입 연산 실습¶

    students = ["김철수", "이영희", "박민수"]
print("초기:", students)

# 맨 뒤에 추가 (빠름 ⚡)
students.append("정지은")
print("append 후:", students)

# 특정 위치에 삽입 (느림 🐢)
students.insert(1, "최하준")
print("insert(1) 후:", students)

# 맨 앞에 삽입 (가장 느림 🐢🐢)
students.insert(0, "강수빈")
print("insert(0) 후:", students)

    실행 결과: 

    초기: ['김철수', '이영희', '박민수']
append 후: ['김철수', '이영희', '박민수', '정지은']
insert(1) 후: ['김철수', '최하준', '이영희', '박민수', '정지은']
insert(0) 후: ['강수빈', '김철수', '최하준', '이영희', '박민수', '정지은']

    💡 생각해보기: insert(1, "최하준")을 실행하면 내부적으로 어떤 일이 벌어질까요? 1번 이후의 모든 원소("이영희", "박민수")가 한 칸씩 뒤로 밀린 다음, 빈 1번 자리에 "최하준"이 들어갑니다.

    Step 3: 삭제 연산 실습¶

    students = ["강수빈", "김철수", "최하준", "이영희", "박민수", "정지은"]

removed = students.pop()

removed = students.pop(1)

students.remove("최하준")

# del 키워드로 삭제
del students[0]

    Step 5: ⚡ 속도 차이를 직접 측정해보자!¶

    이것이 이 장의 핵심 실험입니다. append()와 insert(0)의 속도 차이를 직접 눈으로 확인합니다.

    import time

n = 100000  # 10만 번 반복

# 실험 1: 맨 뒤에 추가 (append)
data1 = []
start = time.time()
for i in range(n):
    data1.append(i)
end = time.time()
print(f"append {n}번: {end - start:.4f}초")

# 실험 2: 맨 앞에 삽입 (insert(0))
data2 = []
start = time.time()
for i in range(n):
    data2.insert(0, i)
end = time.time()
print(f"insert(0) {n}번: {end - start:.4f}초")

    🔥 정리하기: insert(0)은 append()보다 수백 배 느립니다! 10만 개 데이터에서도 이 정도 차이가 나니, 데이터가 100만 개, 1000만 개가 되면 그 차이는 더욱 극적입니다. 맨 뒤에 추가하는 것이 가능하다면, 항상 append()를 사용하세요.

    Step 6: 학생 성적 관리 프로그램 만들기¶

    지금까지 배운 연산을 종합하여 간단한 성적 관리 프로그램을 만들어 봅시다.

    def add_student(names, scores, name, score):
    """학생 추가 (맨 뒤에 추가 — O(1))"""
    names.append(name)
    scores.append(score)
    print(f"✅ {name}({score}점) 추가 완료")

def remove_student(names, scores, name):
    """학생 삭제 (이름으로 찾아 삭제)"""
    if name in names:
        idx = names.index(name)
        names.pop(idx)
        scores.pop(idx)
        print(f"🗑️ {name} 삭제 완료")
    else:
        print(f"❌ {name}을(를) 찾을 수 없습니다")

def find_student(names, scores, name):
    """학생 검색"""
    if name in names:
        idx = names.index(name)
        print(f"🔍 {name}: {scores[idx]}점 (인덱스 {idx})")
    else:
        print(f"❌ {name}을(를) 찾을 수 없습니다")

def show_stats(names, scores):
    """전체 통계 출력"""
    if len(scores) == 0:
        print("등록된 학생이 없습니다")
        return
    print(f"\n📊 전체 {len(scores)}명")
    for i in range(len(names)):
        print(f"  [{i}] {names[i]}: {scores[i]}점")
    print(f"  평균: {sum(scores) / len(scores):.1f}점")
    print(f"  최고: {max(scores)}점, 최저: {min(scores)}점")

    📝 전체 코드¶

    아래는 Step 5의 속도 비교 실험 전체 코드입니다. 복사하여 바로 실행할 수 있습니다.

    """
Chapter 02 - 리스트 연산 속도 비교 실험
"""
import time

def benchmark(operation_name, func, n):
    """연산 속도를 측정하는 함수"""
    start = time.time()
    func(n)
    end = time.time()
    elapsed = end - start
    print(f"{operation_name:20s} → {elapsed:.4f}초")
    return elapsed

def test_append(n):
    data = []
    for i in range(n):
        data.append(i)

def test_insert_front(n):
    data = []
    for i in range(n):
        data.insert(0, i)

def test_index_access(n):
    data = list(range(n))
    for i in range(n):
        _ = data[i]

def test_search(n):
    data = list(range(n))
    for i in range(n):
        _ = i in data

# 실험 실행
n = 50000
print(f"=== 리스트 연산 속도 비교 (n = {n:,}) ===\n")

t1 = benchmark("append (맨 뒤 추가)", test_append, n)
t2 = benchmark("insert(0) (맨 앞 삽입)", test_insert_front, n)
t3 = benchmark("인덱스 접근 list[i]", test_index_access, n)

print(f"\n📊 결과 분석:")
print(f"  insert(0)은 append보다 약 {t2/t1:.0f}배 느립니다!")
print(f"  인덱스 접근은 append과 비슷한 속도입니다 (둘 다 O(1) 기반)")
